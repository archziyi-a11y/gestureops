# 历史原型说明（非当前操作教程）

以下保留早期原型实现与模拟验收背景。其中端口5183、isl-*目标、JOB-2406、“未接入”列表及模拟阶段表仅适用于当时原型，不代表当前能力和数据位置。当前使用以 [总索引](README.md) 为准。

服务端持有作业事实，界面只负责把事实画出来、把点击变成一次服务端动作。
**没有前端状态机**：刷新、换标签页、重启服务，看到的都是同一份 `data/state.json`。

当前包含项目仪表盘、空间总览、资产拖放与上下文组装，以及模拟迁移交接链。部分工作面已接入真实接口，不以模拟迁移代表真实运维完成；调查摘要不代表实时状态。最新交互见 `WORKSPACE-CHANGE.md`。

2026-11-09 已接通线上物料删除和业务提示词实装/回退，见 [管理能力部署记录](ADMIN-MANAGEMENT-DEPLOYMENT-20261109.md)。管理凭据由本机服务读取，不进入浏览器或仓库。

```
顶层左右切项目 → 总览点销售助手 → 部署与迁移
→ 选目标 + 凭据引用 → 检查 → 授权 → 生成并复制提示词
→ 导入匹配的模拟回执（才推进）→ 换目标（旧授权失效）→ 刷新仍看得到发生了什么
```

## 启动

```bash
cd workbench-prototype-v3
npm ci
node server.js
```

打开 <http://127.0.0.1:5183/>。Node 18+；`diff` 用于浏览器本地提示词差异比较。换端口：`PORT=5200 node server.js`。

## 提示词差异对比

回答对比的“本次系统提示词”使用本次请求的原版/修改版快照，不随编辑框后续修改而变动。新增用主题色底纹与下划线，删除用低饱和主题色与删除线，文字修改在左右两侧标出具体字词。按变动行统计，支持上一处/下一处、只看差异（保留相邻一行）；不推断语义是否等价。超出精细比较预算的长文本显式改为整段标记，不截掉内容。

验证：`node tests/prompt-diff.mjs`（需要本地 5185 服务）；`node tests/knowledge-api.mjs` 使用独立临时存储与离线模型，覆盖原有知识与提示词流程。

## 按你那条路径点一遍，每一步会看到什么

| 你点哪里 | 会发生什么 | 可以验证的点 |
| --- | --- | --- |
| 仪表盘底部切换箭头 | 切到下一个项目的观测主题 | 切换走服务端，刷新后还是那个项目 |
| 总览 → 销售助手 | 进入项目操作台 | 新建入口可创建草稿；总览支持自动及手动两至四列密度 |
| 操作台 → 部署与迁移 | 进入迁移准备，步骤条停在 01 | 服务状态与业务产出始终分开显示 |
| 点 `isl-03 · 北京隔离区` | 目标变了；若之前有检查/授权，立刻作废并留下事件 | 「换了目标就等于换了作业对象」 |
| 点 `local-key-ref-03` | 只换引用标识，不读密钥内容 | 凭据变更同样会让旧授权失效 |
| 点「检查迁移条件」 | 五项只读检查：连接 / 权限 / 依赖 / 空间 / 数据位置 | 检查不写任何数据；失败项会写清原因 |
| 点「授权本次作业」 | 授权绑定当前目标 + 凭据 + 范围 | **没检查就不能授权**（按钮是灰的，鼠标悬停有原因） |
| 点「生成并复制提示词」 | 生成 `PKG-JOB-2406-01`，复制到剪贴板，跳到交接页 | **复制之后仍是「待接手」**，不是已接手、不是已执行 |
| 交接页「载入错配示例」→「导入回执」 | 被拦下：「作业编号不一致」 | 作业停回「待接手」，拒绝原因写进记录 |
| 「载入匹配示例」→「导入回执」 | 校验通过，变为「已接手（模拟）」 | 作业编号 / 包编号 / 目标 / 范围签名四项全对才推进 |
| 回迁移页点 `isl-01 · 深圳隔离区` | 检查、授权、提示词、回执一起清空，回到「待检查」 | 「最近变化」条与作业记录都写着：旧检查与授权失效、原因是什么 |
| 按 F5 / 换标签页 | 阶段还是「待检查」，记录一条不少 | 状态不在浏览器里 |
| 顶部「作业记录」 | 每条事件都有 时间 / 动作 / 前后 / 来源 / 下一步 | 包含被拦下的回执，失败也留痕 |

## 状态与门槛（唯一的判定来源：`src/domain/store.js`）

| 阶段 | 含义 | 什么能让它前进 |
| --- | --- | --- |
| `待检查` | 还没检查 | 检查通过 |
| `检查受阻` | 有失败项 | 改条件后重新检查 |
| `检查已过期` | 条件变了但没重查 | 重新检查 |
| `检查通过 · 待授权` | 检查通过 | **单独一次授权** |
| `已授权 · 待生成提示词` | 授权绑定当前配置 | 生成提示词 |
| `待接手` | 提示词已生成 | **一份字段全对上的回执** |
| `已接手（模拟）` | 回执校验通过 | （下一批）执行与验收 |

铁律：

- 配置一变（目标 / 凭据引用 / 范围 / 模拟条件），检查、授权、提示词、回执**一起**作废。
- 重新检查也会作废之前那次授权：授权是独立事件，不会被检查顺带完成。
- 复制提示词不改变阶段；只有回执能推进。回执校验四项：`jobId`、`packageId`、`targetId`、`scopeSig`。
- 一件事只有一种状态描述；状态变了就改文字，不保留旧说法。

## 回执长什么样

「匹配示例」是由**当前配置**现算的（包编号会随新配置变化），所以不存在一份写死的样例糊弄过去：

```json
{
  "kind": "workbench.handoff.receipt",
  "jobId": "JOB-2406",
  "packageId": "PKG-JOB-2406-01",
  "targetId": "isl-03",
  "scopeSig": "code:1,config:1,db:1,materials:1",
  "issuedBy": "接手端 · 本地模拟",
  "issuedAt": "..."
}
```

## 这一批**没有**做

- 其它工作面（画像连接 / 知识资料 / 画像对照）只有入口，点进去是「未接入」，不放假页面。
- 执行与验收（步骤 04–05）：需要另做模拟执行器；现在停在「已接手」。
- 资产池拖放、项目记录里的业务事件回填：下一批。
- 不连接生产、不读真实凭据、不执行真实迁移、不启动真实 WorkBuddy、不派发任何任务。
- 时间一律 Asia/Shanghai，数据全部合成。

## 文件

```
server.js                 静态文件 + JSON API（/api/state、/api/action、/api/receipt-sample）
src/domain/seed.js        三个合成项目、三个目标、两个凭据引用、JOB-2406
src/domain/store.js       状态机、失效规则、提示词与回执校验、事件记录  ← 规则都在这里
src/ui/app.js             路由与视图，只渲染服务端返回的事实
src/ui/styles/app.css     深色、描边分层、状态用「图标 + 文字 + 颜色」三件套
tests/flow.mjs            44 项端到端（含重启后事实还在）
tests/browser-check.mjs   32 项真浏览器点击（无头 Chrome + CDP），会存截图
data/state.json           运行时状态（已 gitignore；删掉即回到初始）
```

## 验收命令

```bash
node tests/flow.mjs           # 需要 5199 端口空闲，自己起临时服务与临时状态目录
node tests/browser-check.mjs  # 先 node server.js；需要本机 Chrome
```

两套都只通过 HTTP / 真实点击驱动，不碰内部对象。
