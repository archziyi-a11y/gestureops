# 空间工作台交付记录

## 已实现

- 六类十二项来源对象；一级卡片与详细仪表盘分离，历史观察明确标注。
- 横向资产栏、单卡原生拖放与键盘替代操作；逐张加入可累积上下文，不使用资产多选。
- 左侧松手后查看；右侧问题与辅助资料组装；一般问题允许批量，严重或未知等级问题独占。
- 已有项目内组合层、新项目命名与描述、增删资产、取消组合、可编辑上下文预览与复制。
- 成功复制 Toast；失败不宣称成功；复制不清空卡片、不标记解决。
- 服务端 workspace.json 保存草稿；原子写盘；版本冲突拒绝静默覆盖。
- 窄屏处理托盘可以展开/收起；桌面左右区域独立浮现。

## 验证

- `node tests/workspace.mjs`：14 项规则检查，一般/严重/未知等级测试数据仅在测试中构造，不冒充真实事件。
- `node tests/workspace-api.mjs`：版本冲突、拒绝不修改状态、重启后草稿保存通过。
- `node tests/flow.mjs`：既有迁移与回执链 44 项通过。
- `node tests/browser-check.mjs`：涵盖已有流程、上下文复制失败与真实剪贴板成功、刷新保存、项目草稿、详情、桌面与390px窄屏；拖放包含 DOM DragEvent 路径和由鼠标发起的 Chrome 原生拖放数据。

## 证据与边界

这是本地交互原型，不是生产运维平台。未读取凭据、未重启业务、未重新执行历史失败任务；未做真实 WorkBuddy 接手验收。
目录数据为代码及2026-11-07本机调查摘要，没有实时健康轮询。未知等级的真实问题保持独占。
项目草稿不是仓库或部署；复制的上下文不构成执行授权。
新演示使用独立 STATE_DIR，保留原迁移演示数据。工作台草稿与迁移状态分别存储，页脚重置迁移演示不删除工作台草稿。

## 启动

在 workbench-prototype-v3 下启动服务，设置 PORT=5185，STATE_DIR 为本机独立演示目录。
入口 http://127.0.0.1:5185/#/grid 。如果端口占用，换空闲端口，不启动第二个进程写同一状态目录。
