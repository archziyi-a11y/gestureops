# 卡片详情优化实施与验收

## 目标

员工打开详情，能判断当前业务是否可用、影响在哪里、下一步去哪里处理。详情展示状态与影响，工作面承接常规操作，上下文组装承接复杂排查。不把维护手册全文搬上页面。

## 共同约束

- 用结构化观测字段渲染，不从拼接的说明文字反向提取指标。
- 当前观测、最近执行、历史调查分别标明；读取失败不能回退成当前历史告警。
- 无请求、无新增、未启用、外部触发未运行不自动判故障；缺失计数不填零。
- 单对象成功不代表全量成功；调度器结束码不代表业务完成。
- 首屏给结论与影响，业务明细按主题展开，来源与技术依据默认折叠。
- 不新增与拖放、工作面重复的操作入口；不自动运行修复、采集或消息发送。
- 保留深色、克制的金色强调与现有详情浮层交互。桌面与窄屏均不得文字溢出。

## 每张卡的工作流程

1. 列出使用者最关心的三个问题。
2. 核对采集代码、回执与维护手册，建立字段、来源、时间和范围对应表。
3. 定义正常、无活动、部分完成、失败与观测失败的业务措辞。
4. 实现业务主题布局，不强求相同类型或相同数量的指标。
5. 检查卡片摘要、详情、维护上下文的状态和范围一致。
6. 用隔离样例覆盖状态分支，用浏览器检查真实渲染、折叠交互和响应布局；记录未覆盖部分。

## 第一批必须覆盖

- 单群成功但全量任务失败，两项事实同时显示，不清除全量问题。
- 调度器不可读但有效业务回执存在，仍展示该回执的有限范围。
- success 且零新增，显示没有新增，不判采集失败。
- partial 区分未扫描完成与已扫描但素材待补。
- 回执字段缺失、损坏或无效，不显示虚构资产数量。
- 原始日志、客户正文、凭据不得因增加结构化字段泄露到浏览器。

本轮只优化观察与交接体验，不据面板测试宣称实际采集、消息送达、生产部署或故障修复完成。
