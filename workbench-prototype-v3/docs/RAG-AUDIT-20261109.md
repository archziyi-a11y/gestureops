# 试问对比与 RAG 链路体检

## 系统提示词管理（本页试问）

目标：在同一试问工作面编辑、保存历史版本并比较提示词。生产 sales_prompts.py 的帮我回/润色/销售指导合同不同，不由此页自动替换。

- 知识库效果：两侧使用相同的编辑中提示词，仅改变是否提供资料。
- 提示词效果：原版来自所选已保存版本，修改版来自编辑器；检索仅执行一次，两侧共用该次资料、问题、范围与模型。
- 保存新版本写入服务端 trial-prompts.sqlite3，历史不可覆盖；携带最新版本号，冲突拒绝并提示刷新。选历史版本可还原到编辑器再保存新版本。
- 结果保留当次提示词快照；输出 JSON、引用约束由程序追加，不因编辑器修改而取消引用校验。
- 验收：版本持久化/冲突、两侧资料一致、提示词快照与页面版本操作；模型替身不代表真实回答效果。

本机日期：2026-11-09，Asia/Shanghai。代码检查、离线检索与浏览器替身验证；本轮未调用真实模型，未改生产资料。内部题集、来源路径及逐题结果仅保留在本地原始项目与备份中，不随源码发布。

## 当前参数

| 环节 | 实现与参数 |
|---|---|
| 原文 | TXT/MD/DOCX；原始字节保留在 SQLite；单文件 8 MiB |
| 分块 | TXT/MD 按空行；DOCX 按段落、最近标题及表格行，表格行带列名 |
| 大小与重叠 | 单块上限 12,000 字，超限拒绝；无固定长度切割、无滑动重叠；上限是输入保护，不是经过评测的最优块长 |
| 嵌入/向量库 | 未使用，不存在 embedding 同步或向量相似度 |
| 候选检索 | SQLite FTS5，汉字逐字索引；查询连续中文片段仍作为短语；按 FTS rank 排序 |
| 语义选择 | 配置模型后，对最多 80 块 / 60,000 JSON 字符候选进行 LLM ID 选择；不是专门 reranker |
| 回答预算 | 本轮补充：最多 6 块 / 18,000 JSON 字符；整块选择，不截断句子；按原顺序保留能容纳的块，页面披露未纳入数量 |
| 生成 | 按用户最终选择使用 DeepSeek 官方 https://api.deepseek.com / deepseek-flash；独立读取 DEEPSEEK_API_KEY，缺失不回退其他供应商，不修改其他业务模型配置。每侧输出上限 1,800 tokens；界面显示本轮实际配置模型 |

试问交互：空输入点击“对比回答”时固定并提交当时显示的示例，用户已输入的问题优先。等待期间显示真实请求范围提示，不模拟内部思维链；回答可附带面向用户的简短依据摘要，以低饱和文字显示。示例轮播本身不发模型请求。本次切换与交互已做离线/浏览器替身验证，未新增真实模型效果结论。
| 引用 | 必须引用至少一个实际送入回答的片段 ID；未知 ID 拒绝显示回答。尚不验证每条陈述是否被该片段语义支持 |
| 更新 | 发布、替换、撤回在同一事务内更新 FTS 与发布版本，无异步同步延迟；原件和历史版本保留 |

回答预算约束资料 JSON，不等同于整个 prompt 的 token 预算。模型总上下文/token 预算还应结合具体供应商限制评估。

## 同题对比

共用同一问题、学校/项目、年度、模型客户端与输出长度。左侧不接收知识库或右侧回答；右侧只允许依据检索资料回答并引用。两侧提示的来源约束有意不同，因此是产品使用对比，不是严格的模型能力实验；不预设右侧更好。

基线与增强链路并行，但 SQLite 仅在主线程访问。每次点击至多三次模型请求：基线回答、语义选择、增强回答；空库不调用后两项。无自动重试。生成失败按侧保留状态，另一侧成功回答继续显示；新一轮清除旧结果，每次结果绑定提交时的问题、范围、版本和本机 UTC 开始时间。

## 题集与前后对照

历史离线评测使用一份内部培训文档，包含八条原题与两条改写题。原始材料及题目正文未包含在本仓库。

预算调整前后均命中 8/10，不是准确率提升。八条原题全部命中同一完整表格块，反映分块粒度过粗；两条改写题零召回，反映短语检索对改写不稳。该结果只说明当时的离线检索行为，不证明真实模型回答质量或业务效果。

通用复算脚本接受本地文档和显式题集。新题集的结果应单独记录，不可替代上述历史证据。

## 已修复与待办

### 业务提示词版本管理（2026-11-09）

目标：知识试问、帮我回、润色、销售指导各自保存版本；业务库可发布到对应运行功能并回退。
必须保持：保存不发布、跨功能隔离、历史正文不可覆盖、版本名称可自定但文件名尾部时间不可移除。时间由保存进程时钟生成，使用北京时间 UTC+08:00，精确到微秒。

- 页面业务库默认名称为功能名，生成 `<名称>_YYYY-MM-DD_HH-MM-SS-ffffff.md`，按 reply/polish/guidance 分目录。
- 服务新增 `/sales/admin/prompts/{kind}` GET/POST；独立 `SASALELE_PROMPT_ADMIN_KEY` 鉴权，不复用员工设备凭证。工作台连接配置为 `SASALELE_PROMPT_SERVICE_URL` 和同名管理 Key，仅服务端读取，不进入浏览器。
- 发布采用当前 revision 比较；冲突拒绝。回退追加激活记录，不覆盖旧版本。接口返回实际加载正文哈希；网络失败显示结果未确认，先刷新核对。
- 正式生成任务在提交时固定提示词快照；版本和哈希参与去重。发布后仅新任务使用新版本，已有排队任务保持原版本。
- 业务对比使用正式输出校验器和同一输入/检索快照，不套通用试问 JSON。试问没有真实客户画像与完整会话，属于本地场景比较，不代表生产效果验收。
- 关键失败测试：文件篡改、跨库版本、陈旧 revision、非管理员访问、保存后未发布、发布后运行读取、回退、未配置服务和模型失败。

交付范围：本地代码、页面与隔离测试；未部署生产服务、未实装生产提示词、未调用真实模型。部署上述服务版本并配置管理连接后，页面才开放实装和回退；未连接时仅可保存和本地对比。

已修复：回答阶段独立预算；实际送入回答片段与展示引用一致；对比基线不接收知识库；单侧失败不覆盖另一侧；桌面双栏、窄屏纵向布局。

待办：

1. Markdown 标题上下文不自动继承，整张问答表仍为单块；采用结构解析保留章节和表头后，先对固定题集回放。不能把模型补写的上下文当原文。
2. 中文短语召回对改写不稳。比较标准分词/混合召回方案，并同时检查误召回，而不是给这十题添加专用关键词。
3. 语义选择只覆盖有界候选。规模增长时，尾部资料可能不进入候选；向量检索是待比较方案，不是本轮已经拥有的能力。
4. ID 校验不等于引用支持每句事实；需要独立评价回答是否越界、价格年度是否适用、引用是否真正支撑结论。
5. 当前每次打开库都会重建派生 FTS，规模增大后有写锁和启动成本。应采用索引版本迁移，而不是每次查询重建。

本轮没有变更分块或索引。后续若更换它们，先统计完整语料、重建耗时与空间，另建派生索引并核对回放；保留原件、历史发布与当前索引，不直接覆盖。若引入嵌入模型，再估算 API 成本。上述题集可作固定回归起点，但单文档且原题泄漏式命中，仍需扩展异义干扰、跨年度、无答案和真实销售改问。
