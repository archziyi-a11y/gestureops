# 智能体接手入口

你接手的是屹立工作台及其纳管项目，不是空白开发任务。先读仓库 AGENTS.md，再按本入口找到当前任务的真实实现。无需旧聊天记录，也不必读完全部历史报告。

## 开始接手

1. 确认用户目标、对象和本轮授权：只诊断、实施修复、还是执行维护。用户已明确的范围不要反复询问；已有资料自己查。
   只读任务先读接口实现再调用：snapshot 等名称不保证无写入；本轮明确禁写时，文档回填也先作为建议交付。
2. 核对当前实例的端口、PID、启动目录和 STATE_DIR。默认桌面入口5185，不能用另一个测试实例结果代替。路径一致但文件大小、哈希或接口计数不同，继续核对进程的文件视图，不重复搬数据或断言丢失。
3. 阅读 [总索引](../README.md) 对应维护手册，再顺着手册核对真实代码、接口及回执。观测时间、历史结论、假设分开。
4. 写一句本轮目标、业务约束、关键失败情形和验收依据，再动行为代码。纯文档不套发布流程。

## 任务分流

| 用户要做什么 | 优先路径 |
| --- | --- |
| 看是否正常 | 卡片观测 → 详情 → 原始回执；不靠进程存活推断业务成功 |
| 更新工作机、物料、提示词或连接 | 现有工作面及对应API；先看已实现契约，不另造脚本绕过 |
| 部署或迁移 | 销售维护手册与迁移交接；目标、数据范围、凭据引用、停机与切换边界由本次任务决定 |
| 修复杂异常 | 卡片上下文 → 对应维护手册 → 代码入口 → 最小取证与修复 → 逐对象验证 |
| 资料消失 | [运行说明](OPERATIONS.md) 与 [源库说明](SOURCE-LIBRARY.md)，核对实例和存储，禁止先重新上传 |

## 执行规则

后台鉴权、真实对象版本与业务条件必须保留。复制上下文不等于执行授权。普通问题可统一调查，执行仍逐对象记录；严重问题独立处理，可附辅助资产。共享进程、配置、文件或数据库有交叉时串行写入，不能因多卡片而重复重启/补跑。

授权内自主推进，不把选择命令、定位已有配置等劳动交回用户。真实消息发送、生产切换、删除、扩群采集等若超出本轮范围才请求明确决定。无法确定成功的写入先查回执，不能直接重试。

密钥内容不进入提示词、日志或Git；使用现有私有配置引用。遇系统安全工具阻断，不换等价途径绕过。

## 完成交接

按 [CHECKLIST](CHECKLIST.md) 验证。报告分别写已实现、已验证、已部署、未覆盖，附代码/回执入口。更新对应维护手册的当前入口、故障分支、验收及接续；当次数字留在有日期的记录，不堆入通用提示词。若维护路径改变，同步 `src/domain/maintenance-context.js`。不得把用户要求的诊断未执行修复判为失败。
