## 员工完整体验

1. 员工在自己的飞书 Bot 私聊上传 Excel，看到列映射及预览，歧义由原 Agent 追问；确认后得到批次与分行结果。部分失败时在同一批次继续，不重做成功行。维护人员从批次面选择该账号与批次，只读核对回执和双表；明确失败允许限定接续，未知先核实。员工回到原会话收到真实结果，维护台回填独立证据；完成标准是对应行实际消费可见，而非任务已复制。
2. 管理员为已有员工修复个人表权限或字段漂移：账号与表配置页选择员工，系统发现绑定、字段差异与环境，不要求手抄路径。直接检查程序授权及元数据权限，复杂归属冲突交 Agent；管理员看到具体权限/字段影响后授权修复。修复后验证员工可见个人表与总表镜像，失败留在原对象接续。只改配置不能显示“已生效”，分享权限和应用权限分别核验。
3. 维护人员由总览选对接表故障卡并拖入模型连接/服务环境卡，组装一次限定诊断。Agent 先读实际版本、回执阶段与相关配置元数据，提出根因证据和最小修复；授权后执行并核验，再更新手册及上下文索引。员工不承担拼提示词和人工串命令的默认责任。

## 维护上下文与接入顺序

现有 `src/domain/maintenance-context.js:1` 提供通用收尾要求，但 `:14` 后非 geo 返回空字符串；对接表没有故障分支专属组合。dock 页面自身复制文本包含对象和只读边界，却没有真实派发、执行状态及独立回填能力。

建议按故障组合：消息未回复＝消息阶段+连接+模型连接；已回复未见数据＝操作回执+双表标记，不先猜模型；Excel 部分完成＝批次摘要/策略版本+行状态+操作键；权限/字段＝账号授权+应用权限+绑定+schema；发布后异常＝实际版本+发布回执+新连接+受影响链。只带必要脱敏引用，不装入正文或私有账本。不要因“模型连接卡”被拖入就授权调用模型。

P0：增加受限只读桥接，返回运行版本、连接时间、脱敏配置来源、批次/回执/双表分侧摘要；先修正资产读源措辞和过时历史摘要。阻塞是尚无统一管理员观测投影及认证契约，不能直接复用含正文 Pilot 查询。

P1：接明确对象的查询、取消、字段预检与授权变更；补服务端认证、角色、对象版本、幂等键、持久执行状态及独立核验。复用现有内部业务函数，但必须检查其副作用：例如读取函数是否调用建库/建表逻辑，不能把 dry-run 名称当无写入保证。

P2：对复杂恢复与发布接智能体执行器。已有 Python/API 足够的确定性操作不必先做 MCP；只有跨会话 Agent 需要统一受限工具时才补 scoped inspect/reconcile/execute MCP。优先补一份当前服务维护与未知结果恢复 SOP，明确历史模式表不适用当前自动回滚；Skill 只在两条真实隔离接手流程稳定后提炼，不为每个页面都造 Skill。
