## 已核对
现有代码：dock-incidents.js 分类 remote_quota_exhausted；prism-collection.js 识别 99991403；report-card-observations.js 从执行记录分类 quota。operations-reminders.js 目前主要按业务操作记录事件，缺少租户共享额度实体。
官方错误码 99991403 是月度 API 额度耗尽。官方说明额度针对同一租户企业自建应用计入统计的 API，不是 Bitable 独享池，也不是消息配额或模型余额。当前各应用是否同租户须核对后才能合并。
官方管理入口：管理后台 → 费用中心 → 权益数据。已找到管理后台查询说明，尚未验证可程序化查询剩余次数的公开接口。应用活跃用户使用统计不等于 API 配额。

文档包含历史及限时额度，不能用文档中的 10000 或 100 万直接填写当前租户总额。

## 显示位置
1. 总览项目区上方：出现耗尽或临界时显示一条共享服务提醒，不改变整张项目卡底色。名称“飞书 API 本月额度”；附已确认受影响的业务入口。未核对租户前分别记录，不凭都用飞书合并。
2. “飞书与模型连接”资产详情：飞书额度独立于模型账户余额。显示剩余次数、总额、统计周期、数据更新时间和来源；下方列实际受影响任务。这里是完整信息的唯一主位置。
3. 各业务仪表盘只写业务影响并关联共享提醒，例如“日报暂不能取数”；不重复堆额度解释。Bot 可用范围、429 限流、JSON 解析错误仍单列。
4. 拖入右侧上下文时，多个业务共用同一额度证据，只组装一次根因资料，各业务失败与恢复验证分别保留。额度耗尽属于常规外部资源问题，不因跨卡自动升为严重事故。

## 进度条合同
- 语义固定为“剩余”：填充宽度 remaining / limit；旁边明确“剩余 N / 总额 M 次，本月”。余量低可用主题金色，耗尽显示明确文字与警示图标，不仅靠颜色。
- 数值必须来自同租户、同统计周期的权威快照。保存 tenantRef、periodStart/End、时区、limit、used、remaining、source、observedAt；边界不明确不自行填日期或比例。
- 只有错误码时显示“最近请求报告额度已用尽”，不伪造 remaining=0 或 limit，不绘制虚假满/空进度条。数值查询失败保留上次快照并注明时间，不覆盖成 0。
- 跨月旧快照不得显示为本月；自然到月初不自动标恢复。额度恢复与各任务恢复分开，不能由某一次接口成功解除全部业务故障。
- 默认提醒候选：已用 90% 与 100%，与官方预警层级一致；阈值可后续按实际业务消耗调整。
- 下一步先核实管理员权益数据页面是否可稳定读取/导出，再选 API 或已授权后台采集适配器。没有数据源时不以手填/本地计数冒充自动查询。避免为了查额度重复调用已耗尽的业务接口。

## 验收
同租户多卡去重、不同租户隔离；未知总额不画比例；过期快照保留但标旧；单接口成功不关闭共享事件；余额与权限/限流不混类；上下文保留业务逐项恢复条件。
