## 使用流程

进入页面自动读取两条连接：销售业务、知识与回答调试。显示模型、端点、配置状态；Key 不回显。

更换销售 Key -> 保存 -> 快速重载 -> 回读确认已载入。快速重载不重启容器，有排队或运行中的生成任务时拒绝并提示稍后再试。知识调试按请求读取配置，保存后下一次请求采用新 Key。

测试连接仅查询模型清单；查询余额使用官方 `/user/balance`，显示服务商账户余额及查询时间，不生成回答。余额不是单个 Key 的独立额度。保存配置与载入配置分别记录 revision，旧页面不能覆盖新配置。

## 配置与保护

- 销售配置位于服务数据目录 `model-connection.json`，临时文件原子替换，权限 0600；启动时同样加载，容器重启不丢失。
- 知识配置位于当前 Windows 用户 LOCALAPPDATA/Sasalele/knowledge-model.json，仓库外；不提交。
- 管理接口复用管理员鉴权，不接受普通工作机凭据。浏览器写请求限定本地同源 JSON；Key 经 stdin 传给本地桥接程序，不放命令参数。
- 不自动测试生成、不自动换模型、不把余额未知写成零；请求结果未知时重新读取核对。

## 自动余额检查

工作台后端默认每 60 分钟检查 sales（销售业务）、knowledge（知识调试）、dock（对接表主模型）三条连接，人民币余额严格小于 5 元时提醒。间隔可设 5–1440 分钟，阈值可调；设置与最近结果保存在实际 STATE_DIR 下的 balance-monitor.json，默认是工作台 data 目录。关闭浏览器不影响检查，关闭工作台服务则停止；服务启动后补查已到期项，不补跑停机期间每个时段。

2026-11-11 代码核对：定时器覆盖三条连接，connections 资产卡当前只投影 sales/knowledge；两者覆盖范围不同。间隔按 lastAttemptAt（最后尝试）计算，不按 checkedAt（最后成功）。GET /api/balance-monitor 只返回实例内存快照，不主动查供应商；定时器是否启用、运行实例是否加载当前代码仍需现场核对。相同余额不证明同一账户；无成功值不能写成余额为零或保留了上次余额。

余额偏低只改变余额文字为主题金色，旁边带警示符号和文字；不改变项目卡背景和边框。持续偏低不重复生成事件，恢复到阈值及以上解除。失败保留旧余额、观测时间和提醒，并标记更新失败；非人民币/无有效金额不作人民币阈值判断。页面每分钟读取本地缓存，不每分钟请求服务商。

GET /api/balance-monitor 返回 connections、alerts 和有界 events，供后续统一运维提醒接入；此轮尚未接入全局通知中心。余额接口无账户 ID，不能凭相同余额把不同 Key 合并为同账户，当前按连接分别记录。

离线验证：threshold/recovery/repeat suppression/failure retention/currency/persistence/scheduling/settings/in-flight sharing；脚本 tests/balance-monitor.mjs。自动与手动查询共享同一结果及并发请求。测试环境可设置 BALANCE_MONITOR_DISABLED=1，避免无关测试访问真实账户。
