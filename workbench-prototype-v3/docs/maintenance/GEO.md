# GEO 自动撰稿维护手册

适用：2026-11-10 核实的本机 OpenClaw 写稿验证链。操作者为接手智能体；不包含自动发布授权。

## 正常结果与入口

- Windows 任务 `GEO-OpenClaw-Write-Validation`：周一至周五 10:30，北京时间。
- 运行环境 `D:/Dev/openclaw-geo`；入口 `bin/run-daily-write-validation.ps1`。先阅读脚本，不直接执行。
- 写稿编排：`C:/Users/YL-GHL/.kimi_openclaw/workspace/war-rooms/qingmei-geo-campaign/scripts/openclaw_write_orchestrate.py`。
- 每次核对 `logs/validation-ledger.jsonl` 与 `logs/write-{date}/orchestrate-summary.json`；成稿位于作战室 artifacts，gate.path 指向对应文件。
- 正常需同一批次回执成功、稿件非空、规则门禁通过。退出码、端口监听、模型返回成功均不能单独代替成稿验收；门禁通过不等于事实已人工审核。
- OpenClaw Gateway 18789；旧 kimi cron、n8n 三条辅助流程与 Windows 写稿任务不能混为同一调度，不同时启用以免重复执行。

## 诊断顺序与分支

1. 记录本机时间/时区，读取任务状态、触发器、最近/下次运行时间。暂停先找原因，过期先查主机是否开机、登录条件和触发器。
2. 查实际运行进程与 Gateway 日志；只读必要错误类别，不导出配置中的密钥或全量会话正文。
3. 对齐本次日期、slot、agent 和 gate。若回执缺失，先查稿件与在途进程，禁止直接补跑。
   摘要可能嵌套完整提示与业务资料。必须先解析 JSON，只投影日期、slot、状态、退出码、gate 结论及产物路径等必要字段；不要整体打印 summary 或嵌套 agent/prompt。核验非空产物只读文件元数据即可。
4. 模型连接失败区分认证、额度、限流、网络与超时。参考真实错误，不自动换模型/Key；超时先确认远端调用与落盘是否完成。
5. 门禁失败查看失败项。仅在明确授权后修稿或修实现；不能降低门禁让旧稿变成通过。
6. 文件不存在、为空或路径越界时，保留记录并定位写入路径/权限/磁盘；不覆盖历史稿件。
7. 未覆盖的错误：沿调度、连接、执行、文件、门禁逐层缩小范围；事实与假设分列。发现与文档冲突，以现场证据记录偏差，不擅自改变业务目标。

## 修复与验收

默认允许只读诊断。启停调度、修改配置、重跑模型、删除、发布须取得具体范围授权。发布仍受 D034 禁止约束，不能用一般修复授权解除。

`run-daily-write-validation.ps1 -DryRun` 仍会创建批次目录并追加台账，不是只读探针。只读检查应读取脚本、调度与已有回执，不以参数名称推断无副作用。

修复后只验证受影响步骤。涉及真实写稿时必须指定日期、slot、次数上限，并先检查既有产物；不得补发整个历史队列。恢复调度先核对下次运行，不把“启用成功”写成“产稿成功”。

## 风险与接续

原因未知、跨系统或证据矛盾为复杂度信号；泄密、覆盖数据、错误外发/重复发布为严重风险；执行结果未知先核对，禁止自动重试。严重任务独占，可附带相关依赖资料。

接续回执记录：目标、检查时间与时区、代码/配置范围、已做动作和结果、未完成/未知项、产物索引、下一步。只保留必要元数据，不保存 Key 或模型完整会话。新智能体先复核当前状态，再从未完成步骤继续。

## 当前验证范围

每次处理结束，执行生成上下文中的“处理后的维护交接”：核对并更新发生变化的入口、依赖、诊断与验收依据；保留历史回执，临时办法注明期限与撤销路径。没有变化记“已核对，无需更新”。更新上下文不授权放宽权限，也不能代替卡片的实际状态采集。

手册入口与调度、成稿回执已核对；上下文分支有离线测试。尚未用全新智能体演练故障修复，不宣称自动运维已验收。
