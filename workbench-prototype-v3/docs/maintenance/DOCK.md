# 对接表 Agent 维护入口

## 2026-11-10 提醒与交接收尾

目标：沿用销售助手提醒样式，将对接表真实操作回执和本地只读观测接到仪表盘、资产卡片和维护上下文。不得将历史失败、取消、过期或业务待补直接认定为当前故障。

- 追问预览/发送、配置测试/保存/重启现在登记结构化提醒。额度耗尽与短时限流分开；账号权限和卡片开关有独立排查分支。连续失败可转智能体，原因明确的额度问题不因重复观察升级。
- 严重对象冲突与结果未知分别保留，单独交接；卡片已被接受但回调绑定失败时明确保留发送事实。当前接入覆盖工作台操作回执，不宣称后台全部异常已连续采集。
- 同一批次的成功预览才可关闭其读取失败；其他批次成功、配置读取成功不消除它。发送结果未知不自动关闭，也不自动重试。
- 仪表盘读取服务、批次、绑定和同步账本；时间来自本机观测接口，显示北京时间。账本状态不冒充远端一致性检查。后台消息吞吐与逐条写入告警仍需后续接入结构化运行回执。
- 组装上下文按额度/限流/访问/发送未知/回调/对象冲突生成检查步骤，包含批次或脱敏对象引用、时间、证据与恢复条件；不包含预览令牌、密钥或客户正文。完成后复核本手册并更新有效变化。

验收：`node tests/dock-incidents.mjs`、`node tests/operations-reminders.mjs`、`node tests/maintenance-context.mjs` 与浏览器回归。离线故障样本不计生产故障；本轮不发送员工消息、不修改业务表。

适用：品宣市场对接表，2026-11-10 工作区。不要扩展到入学表或其他私域同步。

## 按现象定位

常规连接维护可直接在“运行与排查”完成：读取飞书机器人、主模型、备用模型配置，测试当前输入，保存配置，再单独确认重启 AFTB-Bot。密钥留空保留；修改接口域名必须提供对应新 Key。备用模型继承 PXKB/MKTCI 时，保存只写 AFTB 专属覆盖，不改共享来源。

测试仅检查机器人令牌或模型目录，不发业务消息、不调用生成、不写表。保存产生原权限的相邻配置备份，作业记录不存密钥；页面保存不自动重启。重启检查服务进程是否更换，之后仍须按具体问题核验消息或写入结果。旧版本冲突请重新读取，结果未知不要重复执行。

| 现象 | 核对链 | 不可跳过 |
| --- | --- | --- |
| 消息没响应 | 服务 → 连接 → 指定消息阶段 → 模型/回复回执 | Running 不等于连接成功；只查必要元数据 |
| 回复成功但表里没数据 | 操作键 → 操作回执 → 个人表/总表分侧结果 | 回复不是写入证明，不默认重放 |
| Excel 部分完成 | 同一批次 → 行结果 → 操作键 → 剩余项 | 成功行不重复；未知先核实；取消不撤销既有写入 |
| 权限或字段错误 | 工作账号 → 绑定 → 应用权限/分享权限 → schema | 不自动扩权，不重复建表 |
| 发布后异常 | 实际部署版本 → 发布回执 → 配置 → 连接/业务验证 | 不按过时默认值回滚 |

只读检查不得调用会初始化生产库的构造器。查询 operation_status 前先确认入口不会建库或迁移；当前工作台使用只读适配器查询既有记录。服务重启、变更配置或写飞书必须明确对象与范围。修复后验证受影响对象及必要拒绝路径；记录失败、未知、部分成功，不改写旧回执。

维护完核对本文、接口与上下文组合分支。有证据的变化更新，推测标待核实；未变化无需重写。

## 主模型余额

运行与排查读取已保存的主模型配置，通过供应商余额接口查询，不调用模型生成。沿用工作台余额定时器（默认每 60 分钟，服务运行期间有效），人民币余额低于 5 元产生对接表提醒。显示成功查询时间，失败保留上次结果，不计零、不做币种换算。时钟为工作台主机，页面展示北京时间。

2026-11-10 真实只读查询：当前 SiliconFlow 主模型余额接口返回 404/410 类不可用响应，尚未取得余额；页面保留供应商账户控制台入口。不要以模型目录测试成功推断余额接口可用，也不自动更换供应商或 Key。

## 批次待补卡片

批次与待补 → 选择批次 → 预览待补卡片 → 确认发送。复用 `excel_supplement_queue` 的既有卡片及回调，按当前个人表数据、行回执和批次绑定计算真实缺项；错误或未知写入不直接当成缺字段。预览不改员工会话。确认前再次核对配置、批次、缺项和会话版本，仅发送到该批次原会话，不允许从页面指定其他收件人。

本地预览有效期 10 分钟（主机 UTC 时钟）；发送结果及防重发记录存在工作台状态目录的 `dock-followup/followup.sqlite`。不要为重试而删除该文件。飞书接受与实际送达分开；接续绑定失败保留接受回执，结果未知先核对原会话，不重复发送。员工点击卡片选择行，再回复补充内容，沿原续填流程处理。

2026-11-10 真实预览：批次 495C6AEC 的飞书 batch_get 返回 HTTP 429 / code 99991403，响应原文为 `This month's API call quota has been exceeded`。早先“短时限流、稍后重试”的分类错误，已修正为月度额度用尽；99991400 或不含额度错误码的 429 才按短时限流处理。请管理员核对飞书后台调用额度与套餐，额度恢复后重新预览；不循环重试、不以历史缺项代替当前记录发卡。未发送员工消息。离线覆盖卡片发送、回调绑定、并发会话、过期、防重复和未知结果；真实卡片发送及员工回复续填仍待验收。
