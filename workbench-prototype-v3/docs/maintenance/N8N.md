# n8n 共享平台维护

## 职责与入口

平台卡负责运行、访问、持久化与调度依赖；任务内容及送达由对应业务卡负责。

- 运维入口：`project/docs/OPS.md` 第 3 节。
- TLS、LAN 与 WebSocket：`project/harness/n8n/caddy/README.md`。
- 迁移及依赖：`project/docs/N8N-MIGRATION.md`。
- 本机探针：`https://localhost:5678/healthz`。浏览器交互应核对 Caddy 手册中的 LAN 地址；不要把探针地址自动当成推荐交互地址。

## 平台检查链

1. 只读核对 `pxkb-n8n`、`scs-n8n-caddy` 状态、启动时间、重启迹象。
2. 检查代理与健康端点；HTTP 200 与证书可信、登录成功、WebSocket 正常分别记录。使用跳过证书验证的探针须注明。
   只读提取实际使用的公开证书 SAN、有效期，与本次实际访问的主机名/IP 对照；另查目标设备的系统信任结果。证书未过期不等于地址匹配，地址匹配不等于系统信任。LAN 地址以当前网卡观测为准，不把历史 IP 固化为推荐入口；不得读取私钥。发现不匹配时先确认需要维护的稳定访问入口，再提出重签、信任配置和代理变更方案，不自动执行。
3. 定向读取实际挂载、持久卷、启动配置及调度依赖，核对持久数据位置。不要输出完整 inspect 的环境变量或凭据。
4. 综合健康脚本先审查副作用，可拆出已授权只读检查；OPS 中 POST webhook 示例不是普通探针，会触发业务，不直接执行。
5. 无任务运行不自动判故障。日报问题转 `reports` 卡；外部 GEO 撰稿转 `geo` 卡。不要为平台验收启动所有工作流或读取客户执行正文。

## 完成与接续

逐项列已检查、异常、未覆盖及理由；平台健康无需制造修复。共享容器重启前列受影响任务并协调授权，不让多个接手者各自重启。修改、执行工作流、迁移与补跑遵循本轮明确授权。

维护结果和已确认入口写回记录；卡片现状仍由观测采集，不由文档报告改成健康。2026-11-11 首轮接手记录见 `workspace/experiments/card-handoff-terra-20261111/n8n/`，只验证容器及本机探针，不代表以上检查全部完成。
