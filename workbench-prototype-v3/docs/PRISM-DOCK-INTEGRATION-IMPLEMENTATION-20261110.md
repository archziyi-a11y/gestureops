## 对接表可用性纠偏

### 常规维护接口实施

目标：运行工作面直接管理 Bot、主模型和备用模型连接，提供候选连接检查、配置保存及单独确认的 AFTB-Bot 重启。页面不再以历史同步计数代替维修入口。

必须保持：密钥仅经本机同源 POST/子进程 stdin 传递，不进入 URL、命令行、日志或浏览器持久存储；未填写密钥保留原值。保存必须核对配置版本，防止覆盖其他人的更新。修改 AFTB 专属配置，不修改其回退引用的其他项目凭据。测试不发送业务消息、不写飞书行、不调用付费文本生成。保存、进程重启、业务健康分别回报；提供功能不等于本轮实际重启业务 Bot。

关键失败验收：过期 revision、非法字段/端点、认证拒绝、超时、写文件失败、重启失败，均不得显示成功；后续核验失败不能把已保存配置说成未保存。单元测试使用临时文件与替身，生产只做配置描述读取，实际换 Key 和重启留给页面明确操作。

用户实际走查指出：真实读取不等于日常维护可用。本轮移除三个工作面的重复核对任务表单，历史任务仍在维护记录中；账号页不再显示不可逆表 ID 摘要，改为完整表链接；配置按机器人、品宣数据表、业务开关和独立入学依赖分组，只在运行工作面展示。

必须保持：不删除旧任务、不重复提交已成功业务行、不以配置文件值冒充进程已生效值、不泄露应用密钥；链接仅允许 HTTPS 飞书域。验收包括旧任务可回看、工作面无重复表单、表链接可直接导航及非法链接拒绝。

未完成项：配置保存/重载/生效核验、绑定变更及远端权限检查、真正的待补队列。现有 pilot_obs API 只有观察与审核接口，不提供这些管理写操作；须补真实接口，不用复制提示词或新增手工核对表单替代。当前批次列表仍是导入历史与回执，不代表完整待补处理入口。

## 本轮目标

延续实际代码提取工作面的流程：对接表优先连接现有管理能力，Prism 补齐单批次教学素材写入与读取合同。观察结果在仪表盘；工作面提供配置核对、对象查询与基础排查；复杂修复交给携带证据的智能体。

## 必须保持

- 飞书原有上传、预览、确认不迁移成重复入口。成功、失败、部分成功、结果未知分别保留；未知先核对，不自动重试写入。
- 本地检查不初始化生产数据库、不迁移表、不打印凭据或客户正文。进程运行不表示飞书连接正常。
- Prism 采集、入库、授权读取分别验收；教学素材不伪装成正式笔记。隔离验证不能冒充教师真实使用。
- 保留既有准备任务和历史回执，不以新界面覆盖旧证据。
- 不执行生产写入、部署、重启、外部模型调用或扩大采集。需要具体业务修改时使用明确的对象和操作确认。

## 关键失败与验收

检查缺源、权限、格式与超时；不把读取失败转成空列表。覆盖敏感字段过滤、重复提交、部分结果、未知回执与权限拒绝。页面覆盖自动加载、刷新反馈、对象详情、空数据、失败及窄屏。

Prism 隔离测试覆盖资料事件 → 存储 → 授权读取 → 未授权拒绝；真实批次元数据检查与合成测试分列。对接表覆盖真实本地服务/回执的只读检查与隔离测试，不用已保留历史回执证明当前远端写入成功。
