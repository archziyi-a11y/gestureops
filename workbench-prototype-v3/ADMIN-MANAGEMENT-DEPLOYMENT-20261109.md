## 维护与回退

必须在实际部署目录使用三份 Compose 文件，保留新覆盖文件，否则后续仅使用旧两份文件重建 API 会回到旧镜像并撤掉管理挂载。

部署目录：`<deployment-directory>`。

```sh
sudo docker compose --env-file deployment.env -f compose.yaml -f compose.prebuilt.yaml -f compose.admin-management.yaml up -d --no-deps --no-build --pull never api
```

需要回退服务代码时，在同一目录执行旧组合；这不会删除数据卷，也不会清空已保存的提示词库。回退后管理能力不可用，旧代码恢复使用内置提示词。

```sh
sudo docker compose --env-file deployment.env -f compose.yaml -f compose.prebuilt.yaml up -d --no-deps --no-build --pull never api
```

`scripts/deploy-admin-overlay.py` 是本次一次性部署工具，含基线校验和密钥独占创建，不作为可直接重复运行的通用部署命令。后续部署应重新核实当前镜像与密钥状态。
