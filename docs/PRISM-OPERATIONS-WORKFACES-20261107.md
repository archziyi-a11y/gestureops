## 核心判断

Prism 的维护主线是来源更新、资料入库与完整性、权限读取，部署为支持链。微信本地归档、平台入库、教师可用必须分别验证。不能把已实现的采集器等同于已贯通的教学资料平台。

现有 CURRENT.md 的交接日期为 2026-09-23，其中部署与日常调度尚待确认；不据此断言今天已上线或仍未上线。

## 已核实能力与缺口

### 来源与同步

`D:/Dev/Prism/services/feishu_sync_job/src/prism_sync/job_server.py` 有 dry-run、实写、媒体错误和入库响应处理；`accepted`、`duplicate`、`accepted_with_warnings` 不是同一种结果。

SCS 的 `project/modules/jiaoyan-qun-archive/src/jyq/room_fetch.py` 和 `docs/DEV_ENTRY.md` 定义限定账号、四群白名单、图片与笔记卡片归档，普通闲聊跳过。已有手动 inbox 导入，但这是归档模块的入库，不自动等于 Prism 入库。

页面流程：选择来源与范围 → 预检数量和错误 → 确认执行 → 看批次回执 → 核对平台资源。跨来源汇总、生产调度接入和安全重试范围仍须补充核实；不预设“一键重试全部”安全。

### 资料与入库

`D:/Dev/Prism/services/ingestion/src/prism_ingestion/server.py` 提供事件与媒体接入路径；`services/read_api/app.py` 提供笔记、任务及媒体读取。不能据此声称支持任意文件自动语义整理、全文搜索或通用知识库发布。

页面流程：选待入库资料包 → 对照来源、类型、科目与归属 → 预览重复及缺失媒体 → 入库 → 用目标身份打开实际笔记和原图。详细正文只在授权详情中读取，首屏保留摘要和完整性状态。

与销售助手不同：这里的“补资料”首先是保留来源的教学资产入库，不是给销售模型补知识条目。不得套用销售助手的知识缓存或灰度发布流程。

### 访问与权限

`D:/Dev/Prism/services/read_api/acl.py` 确认：教师原笔记受教师目录归属与科目约束；任务可见性涉及 published；教学素材仅在被正确分类且 visibility=school 时按该分支读取。不能把所有笔记附件都当作全校素材。孤立媒体默认私有。

`identity.py` 与 README 定义可信会话；HTTP 参数和 Demo 角色不能设定身份。正式登录与账号管理接入不能根据 ACL 存在推断已经完成。

第一版页面应支持权限核对任务，不提供无依据的角色切换或直接放权按钮。流程：指定账号和资源 → 核对身份、归属及科目 → 展示应允许或拒绝的依据 → 真实读取验证。资料错误分类与账号权限问题分开处理。

### 部署与服务

`D:/Dev/Prism/contracts/read_api/b1-deploy-runbook-v1.md` 要求反向代理、回环后端、只读仓储和独立 SessionStore；回滚不能随意修改 ingestion 库或媒体。会话库与业务库不可混用。

页面流程：确定环境与服务 → 核对代理、路径和权限 → 准备部署作业 → 启动验证 → 授权身份读取 → 记录结果。域名、部署状态与当前服务健康没有在本轮现场核验，不填虚构值。

## 页面信息和智能体交接

- 入口仅呈现工作主题与必要摘要，不铺满路径和协议。
- 列表显示对象、来源、状态、最近有依据的时间；未知不是零。
- 详情显示批次新增/重复/警告、媒体完整性和读取结果，分主题展开。
- 技术路径、协议映射、授权边界、重试依据进入智能体上下文。
- 时间区分源消息发生、采集结束、平台入库、读取验证和当前观测，不能互相代替。

## 第一条建议打通的流程

选一小批已有教学资料，从来源清单到 Prism 资源建立对应，再以获准身份打开笔记与媒体。它最直接回答“积累是否已经可用”，也能暴露来源映射、媒体和权限之间的断点。

先完成来源批次、入库预览、资料详情和读取验证的可交互页面；未接通处保留明确阶段。不能用生成交接提示词代替真实入库与读取验收。新增来源、扩大采集范围、启用调度或发布公网不属于本次只读调查授权。

## 验收重点

- dry-run 不产生入库成功状态，duplicate 不计新增。
- 图片失败不被笔记 accepted 掩盖；缩略图不等于原图完整。
- 微信归档回执不当作 Prism 入库回执。
- 正确身份可读，错误身份被拒，附件遵循关联资源权限。
- 中断后保留已知结果，结果未知先核对，不直接重做。
- 至少一个真实获准的查找与打开流程，不用资料总量证明教学效果。
