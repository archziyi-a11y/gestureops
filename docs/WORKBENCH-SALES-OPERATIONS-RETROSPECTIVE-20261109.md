# 销售助手工作面复盘：从流程原型到真实维护入口

记录日期：2026-11-09，Asia/Shanghai。范围截至本地提交 `959c22ac`，不是整个项目完成报告。该提交包含 91 个文件，未 push；仓库其他任务仍有未提交修改。

## 1. 这轮真正完成的转变

工作台不再只是展示流程和复制提示词。销售助手的日常维护开始直接连接现有接口，需要连续判断的工作才交给智能体。

| 工作类型 | 交互方式 | 本轮例子 |
| --- | --- | --- |
| 对象明确、规则确定的操作 | 页面直接执行，回读结果 | 工作机查询与更新、团队物料删除、提示词版本管理 |
| 需要语义判断的工作 | 页面保留材料和对比，模型辅助判断 | 资料整理、知识试问、提示词调整 |
| 环境不同、需要连续决策的任务 | 必要输入组成上下文，由智能体按 SOP 执行 | 部署、迁移、中断接续 |

“智能体优先”不等于每个按钮都生成一段提示词。能由接口可靠完成的常规操作，不应让员工再找一个智能体代办。

## 2. 四条工作线的经验

### 部署与迁移：先做真实任务，再决定页面输入

真实备份、隔离恢复和新会话接续，暴露了镜像、数据、配置、权限、工具版本、检查点等依赖。它们必须进入执行上下文，但不必全部变成员工表单。

页面应先问员工“迁到哪里、如何连接、是否切换现用服务”；已有包、脚本和版本由系统与智能体定位。恢复包清单和演练统计属于执行依据，不应成为页面主内容。此前方法文档中“选择备份与目标环境”的员工入口表述，在当前销售助手场景下收敛为“填写目标，系统解析部署来源”；只有确需选择历史恢复点时才暴露备份选择。

本轮真实演练证明的范围见既有迁移复盘，不能外推成所有新服务器、原工作机和生产切换均已验证。

### 工作机：围绕对象操作，不把每个动词拆成页面

增加、查看、更新、停用服务于同一批工作机，适合一个清单加行内操作和新增弹层。方舟后台版本、销售助手版本、安装回执必须分开：下发成功不等于安装完成，历史安装回执也不能充当手机当前版本。

团队统一凭据策略减少员工维护授权文件的负担，后台鉴权仍保留。旧版手机后台无法自动升级时，应直接说明应升级哪个组件，而非无限显示“安装超时”。批量更新以真实安装包和逐机结果为依据。

### 知识与物料：同属内容维护，不代表同一种发布流程

原始资料用于保留来源；整理后的知识供模型检索；团队物料供员工取用；回答调试用于评估知识和提示词效果。这四种对象必须能相互追溯，但不能堆成一个无限增长的上传页面。

先保存原件与来源，再整理、核对、入库和试问。历史参考材料不能仅因已归档就成为现行业务知识。RAG 优化应使用同组问题对比，不能以界面有引用、检索返回片段就宣称回答更准。

### 提示词：完整生命周期比增加按钮更重要

帮我回、润色、销售指导分库保存；版本名可编辑，时间保留。保存、选择、还原编辑内容、实装、回退和删除是不同动作。当前生效版本由服务端回读，不由下拉框推断。

两版差异应直接呈现增删变化，帮助使用者判断修改，而不是让人逐字比对。内置版本和当前生效版本的删除约束必须与界面一致。实装服务未连接、不可操作和正在请求不能都使用等待光标。对外用语统一为“实装”，不在同一流程混用“发布”。

## 3. 这轮反复出现的问题

| 问题 | 原因 | 后续做法 |
| --- | --- | --- |
| 简单操作也要求交给智能体 | 把接手机制当作通用交互模板 | 先查现有 API，再决定是否需要智能体 |
| 页面充满报告、限制和技术路径 | 把工程证据直接当作用户信息架构 | 前台呈现目标、必要输入、结果；详情和上下文承载技术依据 |
| 知识、资料、提示词逐步堆积 | 每次只补新功能，未重走完整体验 | 每增加一种对象，重新检查入口、流转和返回路径 |
| 按钮存在但线上服务不支持 | 本地实现与部署能力没有一起核对 | 调用方、服务端路由、部署版本、结果回读一起验收 |
| 重复刷新、删除入口遗漏、禁用态像加载 | 测试关注功能存在，忽略日常使用 | 检查进入自动读取、无变化反馈、删除、失败和重新进入 |

用户连续走查发现这些问题，说明原验收过于偏重“能点击、能记录”。功能可调用只是基础，还要看用户是否知道操作对象、是否少走一步、是否能判断实际结果。

## 5. 下一项目可复用的工作顺序

1. 查代码、接口、实际部署与已有工具，区分已有能力和设想。
2. 选择一个真实目标，走通正常流程与关键失败分支。
3. 把信息分成系统可查、智能体可查、必须由人决定三类。
4. 按对象和用户目的组织页面，不照搬上一项目的页面数量。
5. 确定常规动作直连、语义工作辅助、复杂任务交接的分工。
6. 完成创建、查看、修改、生效、撤回或删除、失败恢复的完整生命周期。
7. 用真实回读检查结果，再从员工视角删去重复入口和非必要解释。
