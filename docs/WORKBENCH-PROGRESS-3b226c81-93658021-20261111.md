## 二、测试怎样进行

采用每个独立 terra 子智能体只接一张卡片的方式，使用实际生成的上下文，不继承主对话。先限定本轮目标、可读资料、可执行操作和报告归属，再审阅其证据与代码，针对真实缺口调整上下文，必要时定向补测。

测试目录保留初轮及 round2–round9 的记录。轮次中包含启动失败、未完成和补测，不是九轮全量验收，也不能将每次派发都计为成功。

过程中纠正了两项测试设计本身的问题：

- “不写入”不能含糊地排除正常 HTTP 访问日志，否则连已审查的本机 health 都无法核验。后续区分正常审计记录与业务修改。
- 独立测试禁止偷看其他测试答案，不禁止正常 SOP、历史部署交接与验收材料。此前禁令过宽妨碍部署卡接手，责任属于派发设计。

| 部署资料 | 新智能体可找到真实恢复交接与 tools-v2，区分旧工具和已验证范围 | 资料接手不等于新目标迁移完成，不重复解密或恢复来凑验收 |

## 四、员工和接手智能体的体验变化

员工仍使用原来的交互：选项目或问题卡片，加入处理区，复制上下文交给智能体。没有新增一排员工必须阅读的治理说明。

变化发生在复制内容背后：

1. **少找入口。** 任务带对应手册、代码路径、服务或数据链，不再只有项目简介。
2. **少问已有信息。** 可从代码、任务配置和正常历史交接查明的内容由智能体调查；用户主要决定执行目标及影响范围。
3. **更准确地解释状态。** 查询失败、没有历史值、尚未到刷新间隔、业务失败和结果未知分别判断，不用一个“异常”概括。
4. **接手能延续。** 完成后核对手册，记录已验证范围、未覆盖项和下一步；单次余额、PID 等观测留在回执，不塞成永久事实。

最后一张卡还暴露了过宽检索日志的问题。公共上下文已补“先按文件、目录与时间窗定位，再提取字段”。这是执行偏差的改进措施，不将原测试改写成无偏差通过。

## 五、发现的问题不能被测试收口掩盖

| 优先事项 | 已有依据 | 后续工作 |

| 私有路径保护 | 独立报告记录旧 5183 普通私有路径可访问；当前代码 Windows 路径规范化与目录边界存在缺陷 | 优先隔离合成验证、修正静态资源范围，并核对旧实例收尾；不能用 5185 普通路径 403 代替完整验收 |

| 余额文案与证据来源 | 无成功余额时仍可能显示“保留上次余额”；bridge 余额问题可能沿用业务回执来源 | 按是否有历史值分支，并让问题保留真实来源与时间 |
