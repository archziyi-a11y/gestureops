# 屹立工作台 V3.1｜巡视、定位、交接

给实现者：请基于 workbench-prototype-v3 交付可点击的中文原型，不交画册。沿用服务端状态、模拟条件、事件账本与回执校验；不改 V1/V2，不清空已有作业。视觉风格自主决定，交互按下列场景实现。本轮不扩执行器、不新增资产拖放或真实后端集成。

## 一分钟主场景

同事巡视时看出销售助手有一项异常。切到四格找到它，点进项目后，刚才那项异常就标在对应工作面旁边，不需要读第二份摘要。另一位同事没有异常要处理，只想准备一次迁移，也能直接找到迁移入口。在迁移页，他选目标和凭据，看到给智能体的交接内容在同一位置成形。离开再回来，看的是这份作业的实际进展，不是重新开始的向导。

## 三屏要有三种手感

| 场景 | 画面重心 | 操作后的可见变化 |
|---|---|---|
| 巡视：翻项目 | 固定位置显示项目名、最近服务观测、最近业务产出。两项各用一句事实；不强求综合健康分。 | 左右翻页只换项目，不换信息位置。观测未知就写未知。详细记录按需打开；不自动轮播。 |
| 定位：从项目到工作面 | 四格位置稳定；卡上最多突出一条有依据、可归属的异常。没有第四个项目就留出空间，不写设计解释。 | 点项目进操作台，不先放大仪表盘。同一条异常用相同短语和标记出现在对应入口；标记源于同一事实，不硬编码两份。无异常时仍能主动找到低频工作面。 |
| 交接：组装一次迁移 | 主体是目标、凭据引用、范围；底部是一份可展开的交接草稿，不是步骤目录。 | 每次选择在原位更新草稿，未选项写“未选”。窄屏也要看得见刚改了哪项，不让底部栏遮住控件。不跳页去验证自己刚才选了什么。 |

项目操作台使用具体对象名称：部署与迁移、画像连接、知识资料、画像对照、项目记录。视觉上区分未接入与可操作；不为了演示异常编造某个连接已断。若现有模拟数据只有“产出未观测”，就保留这个事实，不能据此断言鉴权失败。

## 迁移页：同一对象，连续反馈

1. **准备。** 只选隔离目标和本机演练凭据引用，不上传私钥。改目标后，草稿中的目标立即改变；若旧配置已验过，在变化处说明“原授权对应目标 A；目标 B 尚未检查”。旧回执保留在历史，不证明 B 成功。
2. **检查。** 当前主操作是“检查目标 B”。失败就在失败项旁显示原因；未做的写“未检查”。通过才出现独立授权操作，授权前明确展示目标、范围、不写生产。不要把未来所有禁用按钮和解释同时铺开。
3. **交接。** 授权后在原位置生成正式交接内容，并可复制。草稿预览不是已签发接手包。剪贴板失败如实提示并可手动复制；不得因此重复授权、重复建包或进入“已接手”。
4. **回来。** 已生成包但没有匹配回执时，主事实是“待接手”。导入错回执显示原因，不推进；匹配后显示“已接手（模拟）”。刷新或另开标签重新读取同一服务端事实，不把页面打开时间当成接手时间。既有执行与验收尚未接入，不补假成功屏。

模拟条件退回独立调试入口。技术依据与详细日志可以展开；影响授权、重试或判断结果的信息不可藏进说明书。保持统一的智能体出口，不新增聊天框。

## 验收方式

- **先不教。** 给首次使用的人两个目标：“看看 Prism 最近是否有业务产出”“找到销售助手的部署入口”。记录第一下点哪里、是否绕路、三步内能否找到；三步是找入口，不是要求三步授权。不具备新人试用条件时单列待验证。
- **再改条件。** 用同一份演练作业展示三帧：已选 A 的草稿；A 已授权后改 B，草稿和授权状态同屏改变；B 重新检查授权并复制后仍待接手。再提交错配和匹配回执验证状态。用可运行页面与真实点验记录交付，不以重绘图片代替。
- **保住旧能力。** 在独立演练数据上运行领域与浏览器回归，不动用户正在试的记录。可随导航结构调整旧测试定位，不删除其业务断言。另测项目切换、异常归属、草稿即时性、复制失败及窄屏遮挡。

交付启动地址、实际验证的路径、未验项目。评审首先看：没有教程时人是否知道去哪，操作之后是否能直接看懂变化；不以页面数量、测试数量或填满版面作为完成标准。
