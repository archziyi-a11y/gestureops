# 从实际代码提取实用工作面

用于把已有项目纳入统一工作台：先查清维护对象、真实能力和完整流程，再设计页面。优先承接必要运维与已有能力的增量维护，不按代码模块数量造菜单。

案例来自 2026-11-07 销售助手工作面的调查与实现。复盘起点为用户指定的 15:27（Asia/Shanghai），不据此推算工时。案例结论对应当次调查，后续复用时应重新核实代码。

## 一 核心原则

**从用户要完成的事情出发，用代码校正流程，用界面承诺完整体验。**

- 必要运维：部署、迁移、授权设备管理、版本核对和运行排查。
- 增量维护：补充知识、更新团队资料、维护已有数据与自动任务。
- 技术模块是实现依据，不天然是一个工作面。
- 界面先行不是静态画稿：操作应产生可观察的对象、状态和结果，失败与中断也能表达。
- 尚未接入执行能力，可以先实现准备与交接，但不能把完整目标降级成“生成提示词”后宣称完成。

## 二 销售助手案例

原菜单混合了部署与迁移、画像连接、知识资料、画像对照和项目记录。它们分别属于作业、技术连接、内容维护、专项调查与历史记录，不宜并列为同一层级。

| 代码调查发现 | 页面决策 |
| --- | --- |
| 工作机已有签发、撤销、有效期和最近成功访问记录 | 增加独立的工作机工作面 |
| 缺少安装版本上报；最近访问不是当前在线 | 不编造在线设备数或版本覆盖率 |
| 团队物料共享库与模型知识加载是两套机制 | 同属知识与物料，内部拆成两个任务视图 |
| 知识缺少完整的文件整理、审核、发布及缓存更新接口 | 保留完整增量链，上传仅完成源资料准备 |
| 有部署配置，但不是完整迁移器 | 保留数据、配置与业务验证步骤 |
| 画像、生成、服务和自动任务有不同排查入口 | 组织为运行与排查；画像对照降为按需调查 |
| 操作台部分告警来自模拟种子数据 | 移除其生产故障含义，不把样例当当前事实 |

最终形成四个工作面：

| 工作面 | 用户要做的事 | 完整完成标准 |
| --- | --- | --- |
| 部署与迁移 | 新环境部署、升级、迁移 | 目标环境、必要数据与业务验证通过；生产切换另有授权 |
| 工作机 | 增减授权、核对访问和版本 | 指定设备授权实际生效或撤销；安装与业务访问分别验证 |
| 知识与物料 | 补充知识或共享资料 | 对应消费方能使用目标版本，来源可追溯 |
| 运行与排查 | 定位服务、客户数据和任务问题 | 明确对象与原因，恢复后核对实际业务结果 |

维护记录成为辅助入口。四个工作面是调查结果，不是所有项目的通用模板。

## 三 可复用步骤

### 1 明确维护场景

列出谁在什么情况下需要来这里，希望改变什么。筛掉纯展示模块、低频专项调查和没有明确消费方的能力。

“增加一台销售工作机”比“设备模块管理”更容易确定输入、权限和结果。

### 2 沿完整调用链核实

从界面或命令入口追到接口、业务规则、存储，再看返回值和消费端。至少核对：

- 对象如何标识，设备与账号是否分开。
- 读取与修改能力分别是什么。
- 数据存在哪里，改变后谁读取，是否有缓存或版本延迟。
- 谁校验权限、对象版本和操作条件。
- 失败、部分成功、结果未知如何返回；重试是否重复写入。
- 现有测试证明了什么，还缺什么实际验证。

不能只看到函数名或成功返回就推断业务闭环。进程存活、接口接受、文件上传与消费端可用是不同事实。

### 3 区分能力成熟度

| 类别 | 处理方式 |
| --- | --- |
| 已有完整能力 | 接入真实入口与结果，补足页面和授权 |
| 已有零件但缺编排 | 补顺序、状态保存、失败接续和结果核验 |
| 尚未实现 | 明确缺口与接入阶段，不用假成功或人工代办冒充完成 |

发现缺口先说明对目标的影响。把智能体工作转回用户、缩小输入范围或降低验收标准的取舍，必须明确提出，不能藏在实现里。

### 4 按职责和对象划分工作面

层级为：**项目 → 工作面 → 具体对象或作业 → 技术依据**。

- 独立工作面通常有独立维护职责、对象生命周期和完成标准。
- 同一对象的新增、修改、撤销放在一起，不机械拆成顶层入口。
- 检查、授权、执行、验证是作业步骤，不是四个菜单。
- 记录、来源和诊断细节按需展开，不与主任务争夺首屏。

### 5 先写体验，再排页面

描述某人进入什么页面、看到什么对象、输入哪些必要信息、操作后改变什么、失败时在哪里继续。

例如：进入工作机页 → 核对已有设备 → 填新增申请 → 智能体按授权签发 → 目标手机导入 → 验证服务访问。申请保存后不能直接显示“设备已授权”。

### 6 分开员工界面与智能体上下文

员工界面呈现当前对象、关键事实、必要输入、结果和下一动作。智能体上下文承接脚本、依赖、数据位置、来源、授权范围和验证方法。

减少解释性小字不等于隐藏硬条件。文件格式、必填项、操作范围必须在操作前说明。上传资料是待处理数据，不是操作指令或授权。

### 7 验证实际变化

覆盖正常路径、关键失败和中断接续，核对调用、返回、保存、回执和消费端的一致性：

- 刷新或重启后，已确认事实仍然保留。
- 重复提交不制造重复业务结果。
- 版本冲突不静默覆盖原文。
- 取消申请不等于撤销真实授权。
- 复制上下文不等于派发、接手或执行。
- 发布后验证实际版本与引用，不只验证上传成功。

## 可复用经验：员工交代目标，智能体承担技术工作

2026-11-09，迁移页从“恢复包检查与历史验证报告”改成“迁到哪里”。前者展示了开发者的成果，却要求员工理解归档、哈希和恢复基线，偏离真实使用目的。

稳定方法不是复制两栏布局，而是分配信息和责任：

| 信息 | 谁承担 | 页面处理 |
| --- | --- | --- |
| 目标对象、特殊安排 | 员工 | 必要输入，明确名称与范围 |
| 已知路径、SOP、历史材料 | 系统 | 自动组织进任务上下文 |
| 当前版本、权限、依赖、事实状态 | 智能体 | 调查并记录，不让员工抄技术字段 |
| 停机、覆盖、撤销与切换 | 有权限的人 | 看具体影响再决定，不因复制自动授权 |
| 进度、业务结果、下一决定 | 页面 | 直接呈现，技术依据按需展开 |

实施顺序：一句话写员工目标 → 查代码与真实流程 → 区分必要输入/可发现信息/决策 → 提供默认安排与少量调整项 → 一个明确交付动作 → 新智能体实际接手验证。简化页面不能缩减真实任务，只是将工作移交给正确的承担者。

常规安排不做成逐项问卷；不要将恢复报告、接口参数、测试数量搬到主页面。材料缺失不能阻止开始调查，也不能被隐藏成“已就绪”。复制成功只代表上下文已取得，不能推进成执行成功。

迁移页已验证字段、上下文、剪贴板与失败分支，尚未通过新版页面完成新一轮真实迁移。详细案例见 [迁移接手复盘](SALES-MIGRATION-RETROSPECTIVE-20261109.md)。

### 下一例：工作机

代码依据：DeviceRegistry 支持 issue/list/revoke；清单有授权时间、撤销与 last_seen，但无安装版本上报，last_seen 也非在线心跳。签发配置须安全传给目标手机、在管理员发机配置导入，再验证实际业务；授权不是员工账号绑定，也不是硬件防复制。

本轮工作面分为增加、查看状态、更新版本、停用。员工提供可辨认的工作机名称和目标；智能体核对真实 device_id、服务器、手机与安装包。名称不唯一时先消歧；版本从手机实际读取，不用源码版本替代；停用仅准备任务，不直接撤销。保留本地准备记录，不能伪装成生产清单。验收覆盖持久任务与复制、取消申请、停用不删除资料、无生产连接时不显示虚构设备状态。

实现与验证：四种任务均可保存并复制上下文，记录由本地服务持久化，增加申请可取消。新增3项任务规则测试及既有13项销售维护断言通过；独立临时服务的浏览器点验覆盖四任务剪贴板、刷新后记录保留、取消申请和桌面/窄屏，无脚本错误。线上清单读取、真实手机操作及新智能体完整接手尚未验收，不把本轮称为已完成设备运维接入。

## 七 接下来按真实接手反推工作面

2026-11-07（Asia/Shanghai）用户确认以下阶段方法。现有页面保留为流程草图，不代表真实运维已接通。

顺序：最小接手准备 → 真实隔离任务演练 → 提炼稳定流程 → 接入页面 → 再验证页面交接。

首条流程是销售助手隔离部署与迁移，由全新 WorkBuddy 会话接手。先调查现有部署入口、依赖、数据与团队物料位置、验证及恢复方式；只补实际缺少的索引、工具或流程，不要求每项能力同时建设 MCP、Skill 和 SOP。页面暂不接入执行器，但演练必须使用真实脚本或 API，不能用模拟回执替代隔离部署。

### 信息缺口如何落地

| 演练中需要的信息或决策 | 应进入哪里 |
| --- | --- |
| 源码、脚本、依赖、数据位置 | 项目索引和自动发现能力，不让用户反复填写 |
| 目标服务器、迁移范围、切换时间 | 用户必要输入与选择；未确定则保持待确认 |
| 私钥、令牌 | 安全引用与受限读取，不进入提示词、普通日志或仓库 |
| 磁盘、权限、依赖是否满足 | 自动检查及其结果，不用人工勾选代替验证 |
| 覆盖、停机、不可逆操作 | 具体操作前的独立授权 |
| 中断、部分完成、结果未知 | 持久运行记录、核对和接续入口 |
| 团队物料访问及业务可用性 | 实际验收证据，不以进程启动或接口接受替代 |

智能体问过的问题不自动变成表单字段。先判定是文档缺失、工具缺失、可自行调查，还是确需用户决策。用户不承担查技术路径、拼命令或人工串联流程的默认责任。

### 演练与验收

- 必须先落实隔离目标、允许访问的资源、密钥引用、测试账号和本次操作范围，再执行远端操作；本方法确认不等于生产或远端执行授权。
- 第一次演练记录每次人工补充：卡在哪一步、补了什么、为何无法自行获得、以后由谁提供，以及对应证据。不得在未记录协助的情况下宣称独立接手。
- 覆盖正常完成和中断接续。下一位接手者须能区分已完成、未完成和结果未知；先核对未知结果，不重复已成功的写入或部署。
- 必须验证隔离环境中的团队物料访问及约定业务结果。仅复制提示词、请求成功或服务存活不算迁移完成。
- 修补接手材料后，用全新会话复验；不把一次智能体偶然采用的命令顺序固化为产品规则。
- 接回页面后，再验证页面生成的上下文足以完成同一流程，执行结果能回到工作台。复制不等于派发，外部报告不等于独立核验。

输出应包含：实际入口清单、人工协助记录、稳定业务步骤、必要用户决策、执行与验收记录、页面调整清单。分别标记已实现、模拟验证、真实隔离验证和生产观察。

2026-11-09 更新：已完成生产盘点、授权短暂停服备份、下载及便携加密包校验；全新 WorkBuddy 会话完成独立隔离恢复及物料读取验证。另一个无旧聊天上下文的 Codex 子会话凭检查点完成接续，原有设备记录保持一致，新增测试凭证已撤销。本地 Caddy→API 的 HTTPS、鉴权、物料及图片校验通过，使用隔离域名和本地 CA，不是生产域名/TLS 验收。原工作机、真实上游、异机恢复及页面交接回填仍未验证。旧部署保留。

### 本次演练反推的页面输入

| 用户选择或决定 | 系统自动读取、检查或记录 |
| --- | --- |
| 选择备份与目标环境 | 包内镜像 ID、哈希、预期物料基线；不能要求用户抄写 |
| 提供密钥引用 | 工具版本、密钥存在性；禁止回显秘密 |
| 确认本次操作范围、停服窗口 | 资源前缀生成与碰撞检查、权限、网络隔离、端口占用 |
| 保留期限及最终切换/销毁决定 | 检查点、执行阶段、通过/失败/未知、临时文件存在性 |

执行器应在读密钥前报告运行环境不兼容；恢复前检查卷根元数据，启动时以真实应用 UID 验证写入权限。明文暂存异常消失保持“原因未知”，不推断成系统常态，也不自动触发全盘搜索。检查点应随任务交付，不能只藏在执行智能体私有会话目录。完整部署验证可分为本地代理/TLS、隔离业务、真实上游和生产切换，不要求一步放开所有权限。

首条流程：当前服务器只读盘点 → 制作并下载可恢复包 → 新会话独立隔离恢复 → 分层业务验证 → 另授权退役旧部署。下载完成不能直接删除旧部署。具体接手任务见 [服务器备份与迁移接手任务](SALES-ISOLATED-MIGRATION-AGENT-HANDOFF.md)。
