# 屹立工作台项目总结

报告日期：2026-11-11，北京时间（Asia/Shanghai）。代码基线：`bf8be880`；上次基线：`93658021`。

范围：Smart-customer-service 项目集中的工作台，以及销售助手、对接表 Agent、Prism 和自动任务接入工作。不将这些业务项目自身的全部开发成果归为工作台成果。现场结果引用既有记录，本次未重新运行生产操作。

## 一、总体判断

工作台已经从可点击原型走到真实业务管理与智能体交接工具。它不再只是把散落系统放进一个导航页，而是把观察、常规维护、复杂任务接手连接在一起：人找到项目和问题，页面完成确定性操作，智能体接手需要调查、判断和修改的工作。

当前适合进入持续使用、具体问题驱动的收尾阶段，不适合继续按卡片数量扩张。主要未完成项是少数真实业务闭环、安全问题收口和外部平台阻塞，不是缺更多页面。不能用一个总百分比同时代表界面完整、接口接通、生产正常和无人值守运维。

最重要的变化有三点：已有能力变得能找到、能调用；已积累资料有来源和去向；维护知识开始脱离旧聊天，能够交给新的智能体。

## 二、愿景与使用对象

最初需求不是再做一套项目管理软件，而是连接已经存在但分散在仓库、服务器、飞书、方舟、Windows 任务和本地文件中的系统。用户画像、教研图片等自动收集已经产生资产，却不一定进入后续消费；即便能力已经实现，也常因入口和维护方法不清楚而难以复用。

工作台的主要使用者是项目维护者及其智能体。员工只需表达业务目的、确认必要对象与信息，不应先学习脚本、配置文件和部署历史。新智能体则应能从稳定入口找到真实实现、现有操作通道和验证方法。

三类责任明确分开：

| 场所 | 回答的问题 | 不承担的职责 |
| --- | --- | --- |
| 总览与卡片详情 | 现在能不能用，哪里有问题，影响什么 | 不把所有技术日志堆给员工 |
| 项目工作面 | 如何完成常规维护和增量更新 | 不把简单操作都转成智能体任务 |
| 上下文组装 | 如何让智能体接手复杂问题或新组合 | 复制不代表执行、修复或发布完成 |

## 三、开发过程与关键转折

### 从界面先行到体验先行

早期原型很快实现了按钮、状态机和模拟回执，但“能点”没有自然变成“好用”：功能被做成教程式引导、长列表和重复操作入口。测试通过只能说明已编码分支可运行，不能说明信息层次符合人的意图。

随后通过手绘和实际点击，形成以项目为入口的空间交互：卡片拖向左侧查看详情，拖向右侧组成处理任务，拖入项目表达能力组合；总览支持密度调整，仪表盘以浮层呈现。去掉重复的查看、组装、操作台按钮，以及与当前动作无关的小字。

“动机驱动”最终体现在页面组织和交互结果，而不是把“你想做什么”贴成一套引导菜单。视觉延续深色、克制强调色和清晰排版，侧边光带提示拖放位置，避免常驻虚线框抢占注意力。

### 从模拟合同到真实流程反推

销售助手迁移是重要转折。模拟流程提出了检查、授权、回执和接续的要求，但真实调查暴露出镜像、数据卷、秘密配置、Windows 工具版本和服务器接入等具体条件。随后先让智能体完成真实隔离恢复，再把实际需要人填写和决定的信息放回页面。

员工最终面对的是迁入环境和迁移目标，而不是恢复包技术清单。复杂细节保留在接手材料和执行记录。该方法也用于工作机、知识与物料、对接表和 Prism：先查实际代码与操作流程，再决定页面边界，不能把一个简单设备列表拆成四套任务向导。

### 从作者自测到独立接手

卡片上下文先交 WorkBuddy，再以单卡独立智能体方式测试。重点不再是“模型能否说出诊断”，而是能否自行找到入口、继承授权、辨别真实与历史、识别共享依赖并留下接续材料。

教研采集测试发现的价值尤其明确：未保护的调用不止图片下载，还包括分页和群成员查询；按消息去重可能掩盖半批附件缺失；单群成功可能错误覆盖全量故障。这些发现促成了实现和上下文同时修正，而不是只改报告文案。

## 四、当前完整使用体验

### 1. 总览、资产和详情

打开工作台先看到项目，再进入相应工作面。资产分为业务应用、自动任务、数据资产、共享服务、连接与资源、开发能力。卡片表达一级状态，详情展开业务影响、观测范围、时间和必要证据。

拖左侧后详情展开，不再留一个重复的接收框；拖右侧后显示本次处理的对象，可查看上下文并复制。一般问题可批量交接，严重问题独立处理并允许辅助资料。等级未知不被默认为可批量执行。

新项目草稿可组合已有资产、填写目标、保存或删除。它是工作设想，不是已部署的业务系统。项目不能把自己加入自己的组合。项目增加时调整网格密度，不被“四宫格”名称限制。

本次提交将业务应用、资料、教研采集、画像、日报、GEO、基础设施等详情拆为独立呈现，减少通用长文本拼接；源文件统计处理零与缺失的区别，修复文字被挤成竖列的问题。

### 2. 销售助手

四个工作面是部署与迁移、工作机、知识与物料、运行与排查。它们服务于不同目的，不靠同级标签反复切换全部功能。

部署与迁移让员工提供目标环境，生成可交给智能体的任务。已有隔离恢复经验包含数据、素材和 API 核对；不能据此宣称生产切换、原工作机或所有上游服务均已完成迁移验收。

工作机以设备清单承载查找、状态、版本和单机操作，并提供增加设备与批量更新入口。团队统一凭据减少逐机授权维护负担，但后端鉴权保留。更新下发、安装回执与手机当前版本分别解释，旧后台不支持自动更新时指向后台升级。

知识与物料分为原件管理、知识整理与发布、回答调试、团队物料。原件不可覆盖，保存来源和用途；创建草稿不等于调用模型或发布。回答调试可比较有无知识以及提示词版本，显示文本差异；帮我回、润色和销售指导各自管理提示词版本、实装及回退。团队物料有真实管理通道，不再只有展示。

运行与排查集中维护模型连接、凭据引用、余额和基础重载。余额轮询与提醒独立于业务运行汇总；帮我回、润色、销售指导、画像生成和同步的成功、进行中、失败用于定位员工“功能没反应”的问题。总览能主动刷新相关观察，不要求先打开子页手动刷新。

### 3. 对接表 Agent

账号与表配置管理业务绑定、表入口和直接依赖；批次与待补按日期组织批次卡片，查看未完成项并发起追问；运行与排查负责连接、配置、余额、测试与基础修复，避免三处重复放同一种核对任务。

追问先依据当前记录生成预览，再确认发送到原会话。发送被接受与员工收到、点击、补充、最终写表是不同环节。真实续填验收仍按维护记录中的缺口处理；飞书额度不足时不能拿旧缺项代替当前数据发送。

### 4. Prism

Prism 整体仍按待部署、待培训平台管理，但教学资料采集已不是纯交接文档。微信图片与飞书教学笔记通过同一教学资料工作面组织，已有图片和笔记分别展示，支持真实批量下载、部分完成回执及本地预览入口。

本地教学页面随归档内容更新；采到、文件可读、结构化候选、平台入库和教师可访问分别表达。平台尚未上线不直接判成生产故障，也不为了凑完整而建立新的教学管理系统。

### 5. 自动任务与基础设施

教研采集、日报汇总、GEO 撰稿、画像链、n8n、Bot 和数据服务分别维护。状态应说明正常频率、通道、最近结果和业务影响，不再把“目录存在”写成可用状态。

共享飞书额度属于跨卡依赖，需要显示影响对象和证据来源；只有取得有效剩余量和总量时才能画比例，不能用一次 quota 错误推造进度条。历史手动触发链零执行不自动判为故障。

## 五、本次提交的实质进展

`bf8be880` 纳入69个文件，4006行新增、299行删除。范围包含详情呈现、采集韧性、诊断可观测性、原件恢复脚本和交接文档；行数不作为完成度指标。

教研采集建立 success/partial/failed 与0/2/1退出码对应，传输重试、逐项隔离、资产级续采、未完成台账及范围窗口回执一起工作。单群运行保留他群待补，不能把一群成功写成全量正常。

11月11日15:33左右的单群实测记录显示：扫描成功、35项已完成跳过、零新增、零重试，manifest保持1813行。这验证了锁、分页、去重和回执，不验证本轮未触发的图片下载与重试，更不证明对端断连根因消失。数据来自该轮维护回执，不是本报告重新采集。

日报诊断补充异常记录能力，四类原因分开：看板地址缺失、机器人可用范围、Bitable月度额度、JSON解析失败。实现可观测性不等于这些链路已经恢复，仍需按实际分支验收。

销售源库恢复解决的是运行实例未读到正确资料的问题。用户终端执行恢复脚本后返回33份、哈希不匹配0；现用接口历史复核为33份、7份待整理、37条来源。脚本保留原件与来源，不用于合并两个不同非空库；有知识关联时须另行处理。相同路径不同进程文件视图的根因仍未确定。

## 六、实现结构与数据责任

本地 Node 服务承担工作台 API 与状态持久化，前端承担展示和交互；业务模块、Python工具、远端 API、Windows调度和n8n提供实际能力。工作台不是把所有运行时重写成一个服务。

桌面启动器默认5185，数据位于 `%LOCALAPPDATA%/YiliWorkbench/spatial-demo`。直接启动默认5183，数据取决于进程cwd。状态、项目草稿、知识文档与源库分别存储；远端业务库、Prism归档并不都在工作台目录。

接口名称不能代替副作用判断。部分“读取”会刷新外部观察或初始化本地存储；未知写入结果须先核对回执，不能无条件重试。凭据留在私有配置，不进入上下文、日志或Git。

## 八、尚未关闭的事项

1. 上一完成度报告记录的私有路径保护问题，本轮没有对应修复验收证据，保持待关闭；不能因文档完善而消失。
2. 当前进程加载版本、实际数据目录与观测来源仍需更直接的产品化识别，减少“文件改了但实例不同”的排查成本。
3. 设备安装、新机配置、知识生产消费、飞书追问回复续填、日报合法发送，各自保留具体业务验收，不以API可调用代替。
4. 飞书额度及应用可用范围由外部平台共同决定；需要恢复后的新证据，而不是反复重跑健康或受阻任务。
5. 教研采集重试和隔离有离线覆盖，正常单群实测未触发网络失败；全量定时结果和真实失败恢复需在后续自然运行中观察。
6. Prism部署培训按项目自身计划推进；本地归档与预览的完成不等于教师生产可用。

## 九、可复用的方法

从真实代码提取工作面：先确定员工要完成的事，再查现有接口、输入、回执和依赖，最后划页面。常规确定性操作直接做，复杂调查交智能体，不将“智能体优先”误解为所有按钮都生成提示词。

界面作为可验证的功能承诺：成功、部分完成、未知和未接入必须来自真实状态；模拟调试用于验证分支，不能永久占据员工工作面。

上下文不是根因脚本：给入口、链路、证据和验收方法，不预写唯一结论。独立智能体产生新证据后，主协作者审阅，再更新手册及生成器。

维护验收检查关系：单群与全量、消息与资产、已有与待补、历史与当前、源文件与发布状态，比孤立函数测试更能发现真实风险。

## 十、下一阶段

第一优先是关闭已知安全与实例识别问题。第二优先是选择一个已有未闭环操作，完成员工发起到业务结果的真实验收，而不是同时扩张全部功能。第三优先是在自然维护中持续检查卡片准确性和上下文接续，不重复无目标地派发所有卡片。

新接手者从 [AGENT-START](../workbench-prototype-v3/docs/AGENT-START.md) 开始；员工读 [使用指南](../workbench-prototype-v3/docs/USER-GUIDE.md)。桌面交接README提供可复制提示词，详细材料仍以仓库为准。
