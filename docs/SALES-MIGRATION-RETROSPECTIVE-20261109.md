# 销售助手迁移与智能体接手复盘

记录日期：2026-11-09，Asia/Shanghai。本文汇总已落盘的 ROUND1–ROUND7 与独立接手报告，不把历史验证当作实时监控。

## 这次要解决什么

让不依赖旧聊天的新智能体，拿到项目入口、恢复包、目标和授权后，能完成部署准备、恢复、验证和接续。管理页面应从真实执行所需的信息与决策长出来，而不是先造一套表单，再要求人补齐所有技术细节。

## 工作经过

1. 从首次部署 SOP 与本地代码反查部署目录、镜像、卷、知识包和共享服务。历史回执提供线索，不能冒充当前状态。
2. SSH 公钥认证与浏览器控制受阻。早期反复解释可能原因、让用户传递调查结果，消耗了协作时间；后来改为直接使用可用的云 CLI 调查现场。
3. 核对实际运行镜像、挂载、数据和共享服务，完成获准的停写备份、加密与下载。源端维护窗口据服务器时钟为 15:51:32–15:51:41（+08:00），约9秒。旧生产部署保留。
4. 在新建 Docker 资源中恢复数据，校验文件、数据库、设备认证和物料读取，避免拿新源码构建的近似版本代替线上镜像。
5. WorkBuddy 不复用 Codex 的容器与卷，独立完成恢复。随后另一个没有旧聊天上下文的 Codex 会话按检查点接续；本地 Caddy/TLS 链路也单独验证。

## 弯路与纠正

- 用户已多次提供系统盘用量截图，仍反复把空间当成未知阻塞，是信息利用失败。实际执行前核查余量有意义，重复索要已有事实没有意义。
- SSH 被拒只能证明认证失败，不能直接认定未绑定密钥或应重启。排查应找能区分原因的证据，而不是列越来越长的猜测。
- 安全边界应限制操作影响，不应让只读调查变成无休止的报告修订。可自动发现的路径、版本、资源和权限，不应让用户重新填写。
- 整卷包含客户派生数据，不能同时声称全量与已排除隐私；脱敏演练包与正式基线须分开标识。
- PowerShell 5.1 的 AesGcm 不支持不是密码错误。工具现于读取秘密前检查运行时。
- 归档卷根目录权限是应用可写的必要条件。工具新增恢复前后核对，而不是统一 chown 掩盖差异。
- WorkBuddy 暂存明文消失原因未查明；不得归因给系统或智能体。流程需要记录暂存创建、使用、删除及未知状态。
- 数据库内设备授权记录不等于上游凭据，不能据此撤销生产授权。

## 可复用做法

先查真实代码和部署事实，形成最小执行包；由全新智能体实际运行；把卡点分别归为工具缺陷、材料缺失、用户决策和未覆盖范围；只修受影响部分，再回填到页面。不要用测试项数量替代业务链路，也不要把复制提示词记为任务已经执行。

传输通道与恢复流程分离。云 CLI、SSH、文件传输只是适配方式；恢复包、资源身份、验证与检查点不能绑定某家云。

## 页面修订：从技术材料转向员工任务

首批页面把恢复报告搬到主界面，偏离了员工只需交代迁入环境的目标。现改为地址、账号、端口与认证引用；停机和访问安排采用可调整默认值。版本、备份、工具与验收记录自动进入接手上下文，不再设置“先检查包才能复制”的门槛。候选快照过期或不可用时，由智能体核实当前来源，而不是让员工解决技术材料。

本轮约束：只读准备，不因复制取得执行授权；本地私钥目前采用路径引用，未实现上传和凭据托管，不能将浏览器文件名冒充可访问路径。失败场景包括目标缺失、端口错误、误粘私钥、材料服务不可用与剪贴板拒绝。验收要求这些错误可见、材料不可用仍可开始调查、所有安排进入上下文、变更表单后不显示旧上下文。本轮不连接服务器。

修订验证：任务组装与包检查4项测试通过；真实浏览器验证空字段、材料服务503时仍可交接、默认值与安排变更、认证切换、复制成功与拒绝、编辑后旧上下文清除；桌面1440px与窄屏390px截图检查通过，无脚本错误或横向溢出。尚未以此新版页面生成的任务进行新一轮真实服务器迁移。
