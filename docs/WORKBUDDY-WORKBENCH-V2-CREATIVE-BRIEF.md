# WorkBuddy 创作委托：屹立工作台 V2

请直接做出第二个可运行的中文工作台。使用新的同级目录 workbench-prototype-v2，不覆盖 V1，不占用其 5178 端口。交付启动入口、源码和实际试用结果。

## 你是产品设计师，不是给旧版换肤

为接手学校业务系统的人和智能体设计一件日常工作工具。它应当有自己的视觉判断。色彩、字体、图形语言、页面构图、组件、导航形式与动效均由你决定。不要沿用 V1 的截图，也不必保留它的页面划分。先按自己的方向实现，不需要等我挑色板。交付时用三句话介绍你最重要的设计选择。

**动机写在设计过程里，不贴在产品界面上。** 不设“你想做什么”“按目的选择”之类入口总表；也不要换个标题保留同一组八张功能卡。先进入项目，让人看到有意义的对象、关系和事实；在合适的位置提供清楚的操作。低频操作也要能主动找到，不能只在异常发生时出现。日常页面不承担产品教程；运维文档仍应方便接手者取得。

例：有人想知道昨晚教研图片收全没有。页面可以直接呈现某次采集及其产出，进入后看到未完成项；不必先教他选择“恢复异常”。至于你怎样布置这条路径，由你设计。常用目的地以三次交互内可找到为目标，不压缩授权和验证步骤。

## 新做体验，继承行为

同目录的 WORKBUDDY-WORKBENCH-UI-BRIEF-20261106.md 是八条业务剧本和模拟验收合同。读取其“八条体验与验收”“迁移作业”“模拟执行合同与试用材料”“交付检查”；旧版配色、页面地图、布局和动机入口要求由本简报取代。workbench-prototype 中的领域逻辑和测试可读、可复用，不能把旧视图当骨架。不要为迁就旧浏览器测试的文字选择器而恢复旧文案。

八条剧本都能实际试用：接手、确认运行、恢复异常、换凭据、迁移、更新知识、调整调度、验证已有资产用途。迁移仍是最深的作业；模拟条件改变后由实际逻辑给出结果，不播放成功动画冒充执行。不接生产、不读真实凭据、不跑真实迁移、不声称已启动 WorkBuddy。服务端集成不在本轮。

## 交付时走两遍

第一遍像刚接手的同事：从项目入口开始，不借助教程或搜索，完成“检查销售助手能不能迁到测试服务器”。再从 Prism 找到昨晚采集未完成的项。记录实际经过的页面与点击；不要把作者自己的点击测试称为新人可用性验证。

第二遍像调试者：更换迁移目标应令旧授权失效；物料状态未知时应先核对，不能重复迁数据库；凭据更新后应能回到原失败任务验证业务；资料发布后应能查到消费端版本。分清模拟结果和未实现能力。

交付三张连续界面截图或可直接访问的页面链接，用同一项工作展示操作前、条件改变后与验证结果。评审看的是信息取舍、可发现性和反馈是否准确，不是与旧截图有多像。
