# 对接表 Agent 工作面调查与实现

2026-11-07，Asia/Shanghai。仅核查源码与历史记录，未访问飞书、私有账本、观测 API 或凭据。沿用[工作面提取方法](CODE-TO-OPERATIONS-WORKFACES.md)。

## 范围判断

员工自然语言录入、Excel 预览确认和续填已有飞书业务入口。工作台不另造一套填表业务，也不以固定口令替代 Agent 理解；承接必要运维、对象核对与维护交接。仅针对 mkt_dock，不混入 enrollment 或独立私域同步。

## 必须保留的事实边界

- 消息发送接口接受，不等于已读，更不等于写入。
- 单条 ExecutionResult 的成功有 committed、wrote 和记录标识约束。不能从回复文案重建业务事实。
- 批次 `batch_new_writes` 与 `batch_recovered` 分列；failed_or_unknown 不应统一显示为可重试失败。
- 个人表成功不能宣布双表完成。建表结果未知先核对创建意图与绑定，不重复建表。
- 程序录入权限与飞书分享权限不同；字段权限与对象版本也必须核实。
- 私有回执账本含敏感映射，不作为普通文件上传。只用必要脱敏引用。

## 已实现的本地页面

四个入口、分主题核对任务、账号与对象引用、初始观察、上下文复制、分侧外部核对记录及维护历史。记录由本地服务端保存，外部报告不自动成为独立验证结果；个人表和总表记录不相互覆盖。时间区分外部含时区的观测时间与本机记录时间。

未接入真实观测 API、员工/表绑定管理、Excel 文件解析、线上重试、部署和飞书写入。页面无一键重试、建表或放权按钮。本地任务准备不是完整运维闭环；后续须接实际对象选择、只读采集、按授权执行和业务核验，不能止于复制提示词。

第一条建议接通：一个有授权的 trace 或批次，只读关联消息、操作回执和双侧结果。先确认能定位真实对象，再设计受控修复，而非要求员工重复录入制造测试数据。
