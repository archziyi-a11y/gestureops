# 统一运行与交接工作台：本阶段开发约定

2026-11-06（Asia/Shanghai）确认。适用于工作台首轮设计、实现和隔离验收。

**界面先行：用界面定义智能体承诺的业务结果，并用同一个界面调试实际执行。** 页面绘制完成不是功能完成。可以减少首批支持的项目和环境，不能把约定由智能体完成的工作转交给用户，或用更容易通过的检查替代业务验收。确需改变承诺，先说明原因与影响，再定范围。

## 产品入口

先选项目，再按动机进入作业。第一条路径是「销售助手 → 部署与迁移 → 检查迁移条件」。项目、环境和作业上下文沿途保留。常见作业入口目标为三步内可达，不压缩必要的检查与授权。一个页面聚焦一个目的；概览呈现结果和下一动作，步骤详情提供判断依据和脱敏证据。

接手包面向没有旧聊天记录的智能体，包含项目入口、运维 Skill、当前环境、依赖、可调用脚本或接口、验收和恢复方法。文档描述怎么做，实时检查回答现在能否做。以同事实际使用的 WorkBuddy 为主要接手者进行实测。

## 每个功能怎样开发

1. **先定承诺。** 在现有作业说明里写清：谁对哪个环境做什么、输入与权限、会改变什么、怎样证明业务结果。
2. **把界面做成调试入口。** 使用者可以改变输入或环境条件并观察相应结果。先用标明来源的模拟执行器走通成功、拒绝和中断分支；接入真实执行器时沿用同一作业输入、状态与回执。日常界面不堆日志。
3. **按完整作业接入。** 人和智能体读取同一份作业记录。分别记录接手包已生成、智能体已接手、步骤已执行、业务已验证；接手与执行状态由实际回执更新。中断后保留已知成功、失败、未执行和结果未知的步骤，重试前先核对未知项。
4. **用实际接手者验收。** 区分界面模拟、真实只读检查、隔离执行和生产运行。不能以模拟进度、进程存活或健康接口成功代替最终结果。

## 首条作业：销售助手服务器迁移

首个可验证交互是「检查迁移条件」：只检查，不迁移。显示目标环境、依赖与数据位置、检查通过项、失败项和未检查项。换成不可达的目标，页面应指出具体失败步骤，不继续报告就绪。

隔离验收：给全新 WorkBuddy 会话项目入口、目标测试服务器与本次授权的本地密钥引用。由它查明代码、配置、数据库与团队物料的迁移范围，执行必要备份与部署，并用测试账号在目标环境验证原有团队物料可访问。私钥由受控执行器使用，不进入接手文档或日志。

再制造一次中断，由下一位接手者根据回执继续，验证已成功的数据迁移不会被盲目重做。达到上述结果，记录为“隔离环境迁移已验证”。生产停机、覆盖或切流必须事前明确授权；本约定不启动迁移。

## 范围与分工

保留八项任务：接手项目、确认运行、恢复故障、维护连接与凭据、部署迁移、更新知识、安排调度、利用已有数据。先打通迁移，再扩展其余流程。暂缓独立备份恢复中心、效果成本分析、系统接入退出管理；迁移本身所需的数据保护仍在范围内。

主线负责界面、作业契约与调试体验。并行数据资产核验负责比较方舟历史画像和销售助手实际画像，以及微信教研图片与 Prism 实际可用素材；核验结论供界面使用，未观测到的状态不显示为正常或零使用。
