# WorkBuddy 开发任务书｜屹立·统一运行与交接工作台

## 交付指令

请直接制作中文、桌面优先、本地可运行的交互工作台。交付可编辑源码、启动入口、项目接手说明和已实际点验的验收清单。读者不用看任何历史聊天。本轮交付八条可试用的界面流程，其中销售助手服务器迁移做深；后续按作业逐一替换模拟执行器。不要只返回设计建议、截图、生成提示词或不可操作的页面集合。

产品服务两类使用者：同事先选项目和工作目的，确认影响范围并验收；新开的 WorkBuddy 会话从项目文档和作业记录接手，不要求人重新描述目标。首页不是聊天框，也不是运维监控大屏。

**运行边界：只写新建的独立原型目录，复用已有前端工具链或选可本地启动的轻量实现。** 全程使用合成数据，不接生产 API、不调真实模型、不读环境秘密、不上传文件到远端、不连接 SSH、不变更任务调度、不切流。技术实现可以简单，下面的操作和结果不能用静态占位替代。做不到的项在交付记录中指出。

## 导航与画面

主路径固定为 **项目首页 → 某个项目 → 为该项目办一件事**。常见操作入口从首页最多三次点击可达；多步验证不受此限制。异常通知可以直达具体作业。浏览器返回、刷新、深链接保留项目与作业身份。

| 页面 | 注意力焦点 | 页面元素 |
|---|---|---|
| 项目首页 | 我来管哪个项目？ | 销售助手、Prism 教学平台、对接表 Agent；每项只有用途、最近可信状态、待处理事项。不展示全量指标。 |
| 项目详情 | 我来完成什么？ | 项目与环境、最近业务结果、待处理作业、按该项目适用性展示的动机入口、接手说明。不是八个等大的按钮。 |
| 作业页 | 这次对谁做什么？ | 继承项目；只收集当前需要的输入。显示影响和一个主操作。检查受阻时留在此页修改，不重选项目。 |
| 运行详情 | 做成什么，接下来怎么办？ | 结论、当前步骤、下一动作。按需展开每步的输入、脱敏结果及关联资源；原作业可从历史记录再次打开。 |

视觉参考：借鉴 Atlassian 的稳定导航、Polaris 的单任务页面、GitLab Pajamas 的渐进呈现。统一浅色、中性背景、青绿色强调、中文清晰字阶和舒展间距。左侧稳定导航、顶部位置与环境、正文单主题；状态同时给文字与图标，不能只靠颜色。按钮有焦点、禁用和反馈状态。若附参考图，只取视觉节奏，不照搬其分类首页、模拟数字、Logo差异。不要为了“精致”增加指标墙、装饰图表或嵌套卡片。

## 八条体验与验收

以下是必须可点击试用的代表场景。每行也是点验用例：从指定入口操作后，检查屏幕结果和作业记录；切换反例时应产生不同结果。界面用简短业务名称，不要照抄本任务书当帮助文案。

| 目的和入口 | 人的交互、系统反应 | 点验终点和反例 |
|---|---|---|
| ① 接手：销售助手 → 接手项目 | 选迁移作业，审阅并下载接手包。包内含项目/环境/作业ID、目的、Skill、模拟执行入口、权限、验收与恢复说明。另提供本地模拟接手回执入口。 | 生成文件后仍为“待接手”；收到与本次作业匹配的回执后才显示“已接手（模拟）”。错作业回执不能推进。 |
| ② 确认正常：项目 → 查看运行情况 | 对照服务连接、最近业务产出和各自观测时间；点击异常可下钻。重新检查只读取模拟状态，不执行任务。 | 服务在线但产出未知时显示两项事实，不判整体正常；健康场景下无需用户再点击。 |
| ③ 恢复异常：Prism → 图片采集部分完成 | 在这一次运行查看已保存与未完成项。已知失败可只重试失败项；结果未知时先核对实际产物。 | 例：24项中已保存22项，重试后验证另2项。重复点击不再保存原22项。恢复操作与原回执都可追溯。 |
| ④ 维护连接：销售助手 → 画像更新失败 → 关联连接 | 自动带入原任务。使用演示凭据选项测试候选配置；成功后确认应用到指定服务，再返回原任务验证。 | 候选无效保留旧版本；测试通过不等于已应用，已应用不等于画像已产出。展示引用与配置版本，不要求输入真实Key。 |
| ⑤ 部署迁移：销售助手 → 部署与迁移 | 按下节完整执行。 | 可达、不可达、中断续接、业务验证失败与成功都能亲自走出。 |
| ⑥ 更新知识：销售助手 → 更新资料 | 本地选择合成文档，预览内容，选择用途和可见范围；遇重复或修订版本，展示差异后再发布到模拟知识库。用测试问题验证消费端实际返回的条目、版本、来源。 | 上传、解析、发布、消费分别记账；解析失败不发布。可撤回新版，再验证消费侧版本。检索为模拟，不宣称真实RAG。 |
| ⑦ 安排运行：Prism → 教研采集 → 调整调度 | 修改时间或暂停，在同页预览北京时间及下次触发；保存后从模拟调度器回读。 | 暂停未来调度不会终止在途任务；回读失败显示“生效未知”，不沿用表单值当回执。 |
| ⑧ 利用积累：销售助手 → 利用已有画像 | 选同一合成工作号/客户，比较飞书历史与助手近期画像的来源、时间、互补或冲突；选跟进场景，对照有无历史资料的示例结果。 | 展示模拟任务实际取用的来源，可记录“试接/补质量/维持现状”；没有消费事件写“未观测”。Prism微信图片与飞书笔记是不同来源，不混算。 |

## 迁移作业：必须能调试的样板

1. **待检查。** 源项目固定为销售助手；选择隔离目标和本地密钥引用（仅模拟标识）。主操作“检查迁移条件”只检查连接、权限、依赖、空间和数据位置，不复制数据。
2. **受阻或可授权。** 不可达：标明连接失败、后续未检查，主操作“修改目标”。可达：显示代码、配置、数据库、团队物料的范围及数据保护措施。变更目标、凭据引用或范围后，旧检查和授权失效。
3. **授权与接手。** 用户明确授权本次隔离作业。作业记录绑定该范围；下载接手包与收到接手回执是两个事件。不假定能一键启动真实 WorkBuddy。
4. **执行与中断。** 模拟执行器按步骤返回备份、传输、部署和验收结果。提供可操作的中断场景：数据库迁移已成功，物料传输结果未知。刷新或换接手者后打开原作业，能先核对物料再接续；不重做已完成的数据迁移。
5. **业务验收。** 服务健康但测试账号读不到原有团队物料时，显示“服务已启动；物料验证失败”，定位失败步骤。修复模拟条件后只重验相关项。成功显示“模拟迁移：业务检查通过”，不能写成真实隔离验收或生产迁移成功。

## 模拟执行合同与试用材料

- 原型含可切换的**演练条件**，放在明确标为“模拟”的调试区，不占据日常工作视图。条件改变输入、依赖或执行器回执，再由程序推导结果；不能用“设为成功”按钮、定时进度条或预写下一屏代替验证。
- 项目、环境、作业、运行、步骤有稳定标识。最少记录操作目标、授权范围、前后状态、结果来源、时间和下一动作。区分未执行、运行中、成功、部分成功、失败、结果未知；刷新后保留作业，可显式重置演练数据。UI与接手包读取同一作业事实。
- 附合成资料两个版本、两种目标环境、两种凭据结果及两类画像样例。日志、下载包和页面均不含密钥。所有示例时间标明 Asia/Shanghai。
- 八条入口都可到达，不为费用中心、通用备份中心、系统上下线管理制作空壳。迁移流程内必要的备份与恢复照常保留。

## 交付检查

在新目录交付源码、启动与重置步骤、可下载的接手包样例、验收清单。实际启动原型并按上表逐项点验；记录入口、输入、实际结果和未通过项。重点复验：换目标后旧授权失效；换凭据后能返回同一失败任务；中断刷新后不重复迁移；发布资料后消费端版本可查。截图只能辅助说明，不能代替交互验证。本次只验界面和模拟执行合同。真实隔离服务器、真实 WorkBuddy 接手与真实业务可用性属于下一阶段。
